## 4. 주요 결정과 이유
| 결정 | 이유 |
|---|---|
| 내부 VM firewalld 끔, 게이트웨이만 iptables (11/22) | 내부망은 게이트웨이 뒤에 있음, 도구 통일, 포트가 막히던 문제 해소. 대신 서비스 인증(Valkey·MongoDB·MariaDB)은 유지 |
| Valkey 저장 끔 | 캐시·세션·중복 방지 키는 사라져도 되는 것만 둠 |
| MongoDB 복제 셋 3대 | Monstache change stream 요구, 1대 장애 시 자동 전환 |
| MariaDB `skip-name-resolve`, 시간대 UTC | 접속 허용을 IP 패턴으로 관리, 저장은 항상 UTC |
| 조회는 Replica, 내 데이터는 Primary | 복제 지연 때문에 방금 쓴 값이 안 보이는 문제 방지 |
| Backend는 가격·게임 테이블에 쓰지 않음 | 쓰기는 Kafka Connect 담당, DB 권한으로 막는 것이 진짜 방어선 |
| Backend 프로세스 1개 | `/metrics` 가 워커별로 갈라지지 않게(API 사용 순위) |
| 현재가·구매 타이밍은 PC 가격 우선 | 콘솔(다나와)은 정가·할인율이 없어 섞이면 할인 표시가 사라짐 |
| 목표가 알림은 같은 가격에 한 번, 더 내려가면 다시 | 중복 메일 방지와 새 소식 전달의 균형 |
| 알림 타이머는 매시 50분, backend1만 | 수집 시각 직후에 보고, 두 서버가 중복 발송하지 않게 |
| 리뷰는 `reviews` 에만 저장(`raw_steam` 에서 제외) | 45만 건 이중 저장 해소, `raw_*` 의 TTL 14일 적용 대상 축소 |

## 8. 작업 방식 메모
- 모든 변경은 브랜치(`<파트>/<NW2-번호>-설명`)와 PR로 올리고, 한 PR에는 한 파트만 담았습니다. 계약(`docs/contracts/`) 변경은 별도 PR을 먼저 머지한 뒤 코드를 올렸습니다.
- 서버 명령은 사람이 직접 실행하고, 삭제·초기화 작업은 영향 설명과 확인 뒤에 했습니다.
- 코드 작성·점검에 Claude Code를 사용했고 `CLAUDE.md` 의 팀 규칙(자기 파트만 수정, 비밀 값 금지, 계약 먼저)을 따랐습니다.
