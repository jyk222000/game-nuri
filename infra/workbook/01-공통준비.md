## 1. 게이트웨이 VM (proxy, monitoring) — 먼저
게이트웨이가 있어야 내부 VM이 인터넷에 나갈 수 있습니다. 어댑터는 `enp0s3`(브리지, 공유기)와 `enp0s8`(내부 네트워크)입니다.

```
# 스크립트 위치로 이동 (레포는 /opt/game-nuri/repo 에 있다고 가정)
[admina@proxy ~]$ cd /opt/game-nuri/repo/infra/network

# proxy 는 pc1 (monitoring 에서는 pc2). 실행 전 스냅샷, 팀장 확인
[admina@proxy network]$ sudo ./gateway.sh pc1
```
> <- 스크립트가 하는 일: 주소·경로·DNS 설정 → IP 포워딩 켜기 → firewalld 끄고 마스크, `iptables-nft-services` 설치 → FORWARD·MASQUERADE 규칙 → `iptables-save` 로 저장·서비스 켜기.
> <- 상대 PC 내부망으로 가는 패킷은 NAT 하지 않습니다(출발지 IP가 그대로 보이게). 그래서 backend IP가 Valkey에 그대로 보입니다.

```
# 성공 기준 확인 (default 경로와 FORWARD·MASQUERADE 규칙)
[admina@proxy network]$ ip route
[admina@proxy network]$ sudo iptables -S FORWARD
[admina@proxy network]$ sudo iptables -t nat -S POSTROUTING
[admina@proxy network]$ systemctl is-enabled iptables
```
> <- `iptables` 가 `enabled` 여야 재부팅 후에도 규칙이 남습니다.

## 2. 내부 VM 15대
```
# 이름이 infra/hosts 에 있는지 먼저 확인 (예: kafka1)
[admina@kafka1 ~]$ hostname
[admina@kafka1 ~]$ grep kafka1 /opt/game-nuri/repo/infra/hosts

# 호스트 이름·고정 IP·게이트웨이·DNS·/etc/hosts 를 한 번에 설정
[admina@kafka1 ~]$ cd /opt/game-nuri/repo/infra/network
[admina@kafka1 network]$ sudo ./internal-vm.sh kafka1
```
> <- 스크립트가 IP를 `infra/hosts`에서 찾고, 게이트웨이는 IP 앞 세 자리 + `.1`(10.0.1.1 또는 10.0.2.1)로 정합니다.
> <- `/etc/hosts` 는 **덧붙이지 않고 교체**합니다(같은 IP에 이름이 두 개 생기는 것을 막으려고). 이전 이름(fe1, be1, mongo1 등)은 쓰지 않습니다.
> <- DNS 값은 스크립트 기본이 `8.8.8.8 1.1.1.1` 입니다. 이미 적용된 서버의 DNS는 문서와 다를 수 있습니다(`docs/infra-status.md` 미해결 8번).

```
# 성공 기준: 게이트웨이와 인터넷, 이름 해석 확인
[admina@kafka1 network]$ ping -c 2 10.0.1.1
[admina@kafka1 network]$ ping -c 2 8.8.8.8
[admina@kafka1 network]$ getent hosts kafka1 mariadb-pr
```

## 3. 시간 · 공통 패키지 (17대)
⚠ 미확인: 기록에는 "chrony·vim·git 등, 타임존 Asia/Seoul, `vm.swappiness=1`"만 있고 명령은 없습니다. 아래는 같은 결과를 내는 표준 명령입니다.
```
# 시간대를 한국으로 (모든 서버. 로그·cron·systemd timer가 이 시간 기준)
[admina@kafka1 ~]$ sudo timedatectl set-timezone Asia/Seoul

# 시간 동기화·편집기·git 설치
[admina@kafka1 ~]$ sudo dnf install -y chrony vim git
[admina@kafka1 ~]$ sudo systemctl enable --now chronyd

# 스왑 사용을 최소로 (DB·캐시 서버가 메모리를 디스크로 내보내는 것을 줄임)
[admina@kafka1 ~]$ echo 'vm.swappiness=1' | sudo tee /etc/sysctl.d/99-swappiness.conf
[admina@kafka1 ~]$ sudo sysctl --system
```
> <- 저장은 항상 **UTC**, 화면에서만 KST로 바꾸는 것이 팀 규칙입니다(`CLAUDE.md`). 서버 OS 시간대가 KST인 것은 cron·타이머를 한국 시각으로 쓰기 위해서입니다.

## 4. 팀 계정과 공용 폴더 (17대)
⚠ 미확인: 계정 이름과 그룹은 `docs/network.md`에 있고 명령은 없습니다.
```
# 공용 그룹과 작업 폴더
[admina@kafka1 ~]$ sudo groupadd gamenuri
[admina@kafka1 ~]$ sudo mkdir -p /opt/game-nuri /DATA
[admina@kafka1 ~]$ sudo chown root:gamenuri /opt/game-nuri
[admina@kafka1 ~]$ sudo chmod 2775 /opt/game-nuri

# 팀 계정 (admina 김준영, adminb 남현식, adminc 이고은, admind 한예찬). wheel = sudo 가능
[admina@kafka1 ~]$ sudo useradd -G wheel,gamenuri adminb
[admina@kafka1 ~]$ sudo passwd adminb
```
> <- 비밀번호는 문서·단톡방에 쓰지 않고 **개인 메시지**로 전달합니다. `passwd` 가 입력창으로 받습니다.
> <- 임시로 만든 `/etc/sudoers.d/admin`(NOPASSWD)이 17대에 남아 있습니다. 팀장 확인 후 삭제 예정(`docs/infra-status.md` 미해결 5번).

## 5. 내 PC에서 접속 (SSH)
```
# 내 PC(Windows는 C:\Users\<내 이름>\.ssh\config)에 예시 내용을 붙여 넣는다
[내 PC ~]$ cat infra/ssh/config.example
```
> <- `10.0.1.*` 서버는 proxy, `10.0.2.*` 서버는 monitoring을 **점프 서버**로 거쳐 들어갑니다(`ProxyJump`).
> <- 내 PC에 `infra/hosts` 를 `/etc/hosts`(Windows: `C:\Windows\System32\drivers\etc\hosts`)에 넣지 않았다면 이름 대신 IP로 접속합니다.
> <- `IdentityFile` 은 각자 키 경로로 바꿉니다. 개인 키 파일은 레포·채팅에 올리지 않습니다.

## 6. 방화벽 정책 (2026-11-22 결정)
| 구분 | 정책 | 이유 |
|---|---|---|
| 게이트웨이 2대 (proxy, monitoring) | firewalld 끄고 **iptables** 사용 | 외부(공유기)와 내부를 잇는 곳이라 규칙이 필요 |
| 내부 VM 15대 | **firewalld 끔**, iptables도 안 켬 | 내부망은 게이트웨이 뒤에 있어 밖에서 바로 못 들어옴. FE 80·BE 8000·ES 9200이 막혀 있던 문제와 도구를 통일하려고 |

```
# 내부 VM 한 대에서 firewalld 끄기 (서비스 영향이 없는 시간에 한 대씩)
[admina@kafka1 ~]$ sudo systemctl disable --now firewalld

# 확인: inactive / disabled 가 나와야 재부팅 후에도 꺼져 있다 (monitoring 은 inactive / masked)
[admina@kafka1 ~]$ systemctl is-active firewalld; systemctl is-enabled firewalld
```
> <- 11/25에 mariadb-pr·re, mongodb-pr, mongo-se1·2, kafka1~3, elk, backup, valkey는 `inactive / disabled`, monitoring은 `inactive / masked`로 확인했습니다.
> <- 방화벽이 꺼져 있어도 **서비스 자체의 비밀번호 인증은 켜 둡니다**(Valkey `requirepass`, MongoDB `authorization`, MariaDB 계정).
> <- 공유기 쪽에 열린 포트: proxy 22·80·443, monitoring 22·3000 만. DB·Kafka·Kibana 포트는 바깥으로 열지 않습니다.
