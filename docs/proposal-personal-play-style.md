# 제안: "플레이 패턴"을 전체 통계 분석에서 개인 기능으로 옮기기

> 상태: **제안 (팀 결정 필요)**. 작성: 2026-11-21, 한예찬 의견을 정리함.
> 관련 문서: `docs/features.md` ④, `docs/contracts/api.md` #4·#23·#24·#25, `docs/analysis-feasibility.md`, Notion "분석 방향" #7.

## 한 줄 요약
"플레이 패턴"은 **모든 사용자의 통계 분석이 아니라, 사용자 개인의 Steam 데이터로 성향을 파악해 게임의 플레이타임이 그 사람에게 맞는지 알려 주는 기능**으로 하자. 이미 명세에 있는 **④ 플레이 성향 맞춤 추천**을 구체화하는 것이다.

## 배경
- 원래 초안(Notion "분석 방향" #7 "사용자 패턴 분석")은 이랬다: *플레이타임 + 업적 달성도 분석 → 알맞는 플레이 타임 기반으로 게임 추천.* 팀장 피드백은 "주제 좋음, 조금 더 다듬으면 될듯".
- 이를 정리하는 과정에서 방향이 **전체 사용자 통계**(리뷰어 플레이 시간 분포, 엔딩 달성률, 시간당 가격)로 바뀌었다. 원래 의도와 다르다.
- 현재 만들어 둔 분석 6번("실제 플레이 패턴", `analysis/gamenuri_analysis/a06_play_pattern.py`)이 이 잘못 잡힌 방향을 따랐다.

## 제안하는 기능
**내 Steam ID로 가져온 업적 달성 패턴으로 내 성향을 파악하고, 그 성향에 맞는 IGDB 플레이타임과 내가 평소 플레이한 시간을 비교해서, 이 게임이 내가 바라는 플레이타임인지 알려 준다.**

### 흐름
1. **연동:** 사용자가 마이페이지에서 Steam ID를 연동한다 (`PUT /api/me/steam`).
2. **성향 파악:** 내 보유 게임의 플레이타임과 게임별 업적 달성률을 본다.
   - 달성률이 높은 게임이 많다 → **올클리어형**
   - 엔딩까지만 하고 업적은 적게 딴다 → **스토리만형**
3. **IGDB 매칭:** 성향에 맞는 플레이타임을 고른다.
   - 스토리만형 → "빠르게"·"보통" (`ttb_hastily`, `ttb_normally`)
   - 올클리어형 → "완벽하게" (`ttb_completely`)
4. **내 기록과 비교:** 내가 평소 플레이한 게임들의 플레이타임과 견준다 (예: 평소 20~40시간짜리를 한다).
5. **표시:** 게임 상세에 *"당신 성향 기준 약 N시간 · 평소 플레이하던 길이보다 길어요/적당해요"* 를 보여 준다. 마이페이지에는 내 성향 요약(올클리어형/스토리만형, 평소 플레이 길이)을 보여 준다.

## 쓰는 데이터 (`docs/collector-test/column-mapping.md` 컬럼 기준)
| 필요한 것 | 컬럼 | 상태 |
|---|---|---|
| 보유 게임·플레이타임 | `GetOwnedGames`: `appid`, `name`, `playtime_forever` | ✅ |
| 게임별 내 업적 달성 | `GetPlayerAchievements` (`appid`별 1회) | ✅ (시험 계정에서 63/71개 조회 가능) |
| 게임별 업적 목록 | `GetSchemaForGame` | ✅ (달성률 계산의 분모 = 전체 업적 수) |
| 게임의 플레이타임 | `ttb_hastily`, `ttb_normally`, `ttb_completely`, `ttb_count` | ✅ (비어 있는 게임 있음) |
| 사용자 식별 | `ResolveVanityURL`, `GetPlayerSummaries` | ✅ |

전체 사용자 대상 컬럼(리뷰어 플레이 시간, 전체 업적 달성률 등)은 **필요 없다.**

## 이렇게 하면 좋은 점
- 원래 의도(사용자 개인 성향 기반 추천)에 맞다.
- 전체 사용자 통계는 한계가 컸다. 리뷰를 쓴 사람만의 분포이고, 엔딩 업적을 가리키는 값이 없어 "엔딩 달성률"을 구하기 어려웠다 (`docs/analysis-feasibility.md` 6번).
- 필요한 컬럼이 이미 수집 계획에 있다.
- 서비스 사용자에게 바로 보이는 기능이라 시연하기 좋다.

## 결정이 필요한 것
1. **분석 6번을 개인 기능으로 옮기고 분석에서 뺄지.** 아니면 "전체 통계" 분석으로 남기고 개인 기능을 따로 둘지.
2. **성향 판정 기준.** 올클리어형과 스토리만형을 나누는 기준 (예: 업적이 있는 게임 중 달성률 ○% 이상인 게임의 비율).
3. **"평소 플레이한 게임"에 어떤 게임을 넣을지.** 끝까지 한 게임만 넣을지, 전부 넣을지. 멀티플레이처럼 끝이 없는 게임은 플레이타임이 왜곡된다.
4. **IGDB 플레이타임이 비어 있을 때의 표시.** 예: 헬다이버즈 2는 `completely`만 있다.
5. **연동 전·비공개 프로필일 때의 화면.** 프로필과 게임 상세가 모두 공개여야 `GetOwnedGames`가 채워진다 (수집 노트 7절).
6. **담당과 일정.** 성향 판정과 비교 계산을 Backend(API 응답 시점)에서 할지, 분석 쪽에서 규칙을 정해 넘길지.

## 한계 (확인하지 못한 것)
- 시험한 Steam 계정은 **1개**이고, 후보 15개와 겹치는 게임은 2개뿐이었다. 성향 판정 기준을 검증하려면 여러 계정이 필요하다.
- 업적이 없는 게임은 성향 판정에서 빠진다.
- 위 판단은 수집 노트와 컬럼 매핑 문서를 근거로 했다. 실제 연동 응답으로 이 흐름을 끝까지 돌려 본 것은 아니다.
