# proxy 수집기 첫 실행 기록 (2026-11-23)

proxy VM(수집 서버)에서 `steam-players`를 처음 실행하고 Kafka → DB까지 확인한 기록이다.
설치 순서는 `infra/collector/README.md`가 기준이다. 여기에는 실제로 확인한 결과와 발견한 문제만 둔다.

## 확인한 결과
| 단계 | 결과 |
|---|---|
| 수집기 실행 | `collector@steam-players.service` 약 5분(19:19~19:24 KST), `messages=1000` 정상 종료 |
| Kafka `raw.steam` | 1000건 |
| Kafka `refined.player_counts` | 1000건 (refiner 동작 확인) |
| Kafka Connect → MariaDB `player_counts` | **0건** (아래 문제) |

실행 중 로그가 안 바뀌는 것은 정상이다. 동접자 수집은 게임 1건마다 로그를 남기지 않고 시작·완료 때만 남긴다
(호출 간격 0.3초 × 1000건 ≈ 5분).

## 문제: jdbc-sink-player-counts task FAILED
`curl -s localhost:8083/connectors/jdbc-sink-player-counts/status` (kafka1):

```
DataException: Could not parse timestamp: value (2026-11-23T10:19:27.082137Z)
does not match pattern (yyyy-MM-dd'T'HH:mm:ssX)
```

- 원인: `collected_at`에 마이크로초(`.082137`)가 붙어 있고, 커넥터 패턴은 초 단위까지만 받는다.
- 마이크로초의 출처: `shared/gamenuri_common/messages.py`의 `utcnow()`가 `datetime.now(UTC)`를 그대로 쓴다.
  `CLAUDE.md` 시간 규칙(`2026-11-19T02:30:00Z`, 초 단위)과 다르다. 파이썬 버전과는 무관하다.
- 같은 패턴(`yyyy-MM-dd'T'HH:mm:ssX`)을 쓰는 커넥터: `prices-current`, `price-history`, `games`,
  `games-steam`, `requirements`, `review-stats`, `review-summary`, `time-to-beat` — 같은 이유로 막힐 수 있다.

## 고치는 방법 (결정 전)
| 방법 | 위치 | 비고 |
|---|---|---|
| ① `utcnow()`가 초 단위로 자르게 수정 | `shared/` (전원 리뷰) | 근본 수정. shared 전용 PR로 올린다 |
| ② refiner가 `collected_at`을 초 단위로 잘라 발행 | `pipeline/refiner/` (이고은) | 앞으로 나오는 메시지만 고쳐진다 |
| ③ 커넥터 패턴에 소수초 추가 | `pipeline/connect/` (남현식) | **비권장.** Java `SSSSSS`는 밀리초로 읽어 `082137`이 82초로 더해져 시각이 틀린다 |

고친 뒤: 멈춘 task 재시작(남현식), 이미 쌓인 형식이 틀린 메시지는 재처리 또는 재수집이 필요하다.

## 수집기 실행 순서 (재확인)
IGDB → Steam → ITAD → 다나와. refiner의 게임 ID 대응표가 앞 출처에서 만들어지기 때문이다.
`steam-players` 타이머는 IGDB 수집 뒤에 켠다(아직 켜지 않음).

## 확인 방법 메모
- 수집기는 Kafka만 쓰므로 proxy에는 DB 접속 정보를 두지 않는다. DB 확인은 DB VM에서 한다.
  - MariaDB: `mariadb-pr`에서 `sudo mysql gamenuri -e "SELECT COUNT(*) FROM player_counts;"`
  - 커넥터: `kafka1`에서 `curl -s localhost:8083/connectors/<이름>/status`
- `scripts/verify_flow.py`를 proxy에서 쓰려면 `KAFKA_BOOTSTRAP=kafka1:9092,kafka2:9092,kafka3:9092`를
  앞에 붙인다(기본값이 localhost라서 안 붙이면 전부 "연결 실패"가 나온다).
