# proxy 수집기 첫 가동 기록 (2026-11-23)

proxy VM(수집 서버)에 수집기를 처음 설치·실행하고, Kafka → refiner → MariaDB·MongoDB까지
데이터가 들어가는 것을 확인한 기록이다. 설치 순서의 기준은 `infra/collector/README.md`이고,
여기에는 실제로 해 본 결과, 발견한 문제, 남은 일만 둔다.

## 1. 한 일
1. proxy에 레포 클론(`/opt/game-nuri/repo`), venv 생성, `collector` 계정, `run-collector.sh`, `/etc/game-nuri/collector.env`, systemd 유닛 설치
2. `steam-players`를 손으로 먼저 실행해 Kafka까지 확인
3. IGDB → Steam → ITAD → 다나와 순서로 한 번씩 실행
4. 타이머 8개 모두 켬 (`systemctl list-timers 'collector-*'`에 8개, `--failed` 0건)

## 3. 발견한 문제와 처리
### 3-1. Kafka Connect 적재 실패 — 해결됨
- 증상: Kafka `refined.player_counts`에 1000건이 있는데 MariaDB `player_counts`가 0건.
  `curl localhost:8083/connectors/jdbc-sink-player-counts/status`에서 task `FAILED`.
- 원인: `Could not parse timestamp: 2026-11-23T10:19:27.082137Z does not match pattern (yyyy-MM-dd'T'HH:mm:ssX)`.
  `collected_at`에 마이크로초가 붙는다(`shared`의 `utcnow()`가 `datetime.now(UTC)`를 그대로 씀).
  파이썬 버전과는 무관하다.
- 해결: PR #68이 커넥터 패턴 10개에서 끝의 `X`를 뺐다(소수 초는 버려지고 UTC로 읽힌다).
  UTC가 아닌 시간대(`+09:00`)로 오면 틀리게 저장되니 UTC로만 보낸다.
- 확인: 반영 후 task `RUNNING`, `player_counts` 1000건.
- 참고: `shared`의 `utcnow()`는 그대로라 계약의 시간 형식(초 단위)과는 여전히 다르다. 필요하면 별도 PR로 논의.

### 3-2. 로그가 안 바뀌는 것은 정상
`steam-players`, `steam-details`는 게임 1건마다 로그를 남기지 않고 시작·완료 때만 남긴다.
진행 여부는 Kafka `raw.steam` 건수가 늘어나는지로 본다.

### 3-3. `verify_flow.py`를 proxy에서 쓸 때
접속 정보를 못 읽어 기본값 `localhost`로 접속해 전부 "연결 실패"가 나온다.
`KAFKA_BOOTSTRAP=kafka1:9092,kafka2:9092,kafka3:9092`를 앞에 붙여 Kafka 줄만 본다.
proxy에는 DB 접속 정보를 두지 않는다(수집기는 Kafka에만 쓰므로). DB 확인은 DB VM에서 한다.

### 3-4. 다나와 상품 → 게임 매칭 실패가 많다 (열려 있음)
다나와 검색 794건 중 약 446개 게임에서 상품이 나오는데, 가격이 저장된 게임은 217개다.
`unmatched` 1257건(수집 3회 합계)의 사유:

| 사유 | 건수 | 성격 |
|---|---|---|
| 상품명 → IGDB ID 매칭 실패 | 618 (49%) | **문제 후보** |
| 에디션 (본편 아님) | 294 | 정책 |
| DLC·확장팩 | 198 | 정책 |
| 플랫폼을 알 수 없음 | 63 | 보완 여지 |
| 해외판 / 비게임 상품 / 본체 번들 | 51 / 24 / 9 | 정책 |

매칭 실패의 패턴(샘플 20개): 제조사 접두사(`캡콤 몬스터 헌터 와일즈 한글판`, `Microsoft Game Studio 포르자 호라이즌 6`),
`한글판`·플랫폼(`PS4`, `XBOX ONE`) 접미사, 한글 ↔ 영어 표기 차이(다키스트 던전 2 = Darkest Dungeon II).
refiner가 상품명을 정확히 맞출 때만 매칭해서 생긴다(`pipeline/refiner/README.md`에도 적혀 있다).

단서: 수집기는 `raw.console` 메시지의 `request.params.igdb_id`에 어느 게임을 검색했는지 넣어 보낸다.
이 값을 후보로 쓰고 상품명 일부 포함 여부로 검증하는 방식을 refiner 담당과 정한다. 수집기는 바꿀 것이 없다.

## 5. 문서가 실제와 다른 곳 (제안만, 수정하지 않음)
- `infra/collector/README.md` 설치 블록에 `sudo mkdir -p /etc/game-nuri`가 빠져 있다(`install`이 디렉터리를 만들지 않는다).
- `infra/mongodb/README.md`는 컬렉션을 `raw`·`reviews`·`games`로 적었지만 실제는 `raw_igdb`, `raw_itad`, `raw_steam`, `raw_danawa`, `games`, `unmatched`다.
- 다나와 수집 주기(6시간)는 한 번 도는 시간이 2.5시간+라 겹치진 않는다. 우선 그대로 두고 오류(403·429)가 늘면 늘린다.

## 6. 확인 명령 모음
수집기 상태 (proxy):
```bash
systemctl --failed --no-pager
systemctl list-timers 'collector-*' --no-pager
for s in igdb steam-details steam-reviews steam-review-summary steam-players itad-price itad-history danawa; do
  printf '%-22s %-11s %s\n' "$s" "$(systemctl is-active collector@$s.service)" \
    "$(journalctl -u collector@$s.service -n 12 --no-pager 2>/dev/null | grep -o 'collect done.*' | tail -1)"
done
```
Kafka 건수 (proxy, 레포 루트):
```bash
KAFKA_BOOTSTRAP=kafka1:9092,kafka2:9092,kafka3:9092 .venv/bin/python scripts/verify_flow.py 2>/dev/null
```
커넥터 상태 (kafka1):
```bash
curl -s localhost:8083/connectors?expand=status | python3 -c "import sys,json; [print(k, v['status']['tasks'][0]['state'] if v['status']['tasks'] else 'NO_TASK') for k,v in json.load(sys.stdin).items()]"
```
MariaDB 건수 (mariadb-pr): `sudo mysql gamenuri -e "SELECT COUNT(*) FROM player_counts;"`
MongoDB 건수 (mongodb-pr, 계정 비밀번호는 프롬프트로):
```bash
mongosh "mongodb://mongodb-pr:27017,mongo-se1:27017,mongo-se2:27017/gamenuri_raw?replicaSet=rs0&authSource=admin" \
  --username gamenuri --quiet --eval 'db.getCollectionNames().forEach(c => print(c, db[c].countDocuments({})))'
```
