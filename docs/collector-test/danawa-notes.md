# 다나와 수집 알아둘 점

`scripts/check_candidates.py`로 후보 15개를 검증하며 확인한 다나와 데이터의 특성과 한계. 기준일: 2026-11-19.

## 1. 검색 결과는 두 종류다
| 종류 | 식별 | 특징 |
|---|---|---|
| 카탈로그 상품 | `productSeq`가 숫자(`pcode`) | 다나와가 여러 판매처를 묶은 상품. 번들명("PS5, 중고/패키지디스크"), 카테고리명, 판매처 수(`shopCount`) 있음 |
| 개별 판매처 상품 | `productSeq`가 `판매처코드_번호`(예: `TH201_97664017`), prodType 3 | 묶이지 않은 G마켓·옥션·11번가·YES24 등 개별 등록 상품. 제목은 판매자 임의, 번들명 없음, 가격은 단일 판매처 가격 |

- 초기 파서는 숫자 `productSeq`만 읽어서 **개별 판매처 상품을 전부 놓쳤다.** 위쳐 3의 Switch판 개별 상품(81,780원 중고 등)이 그 예다.
- 개별 상품은 `source="shop_listing"`으로 저장한다. 판매처명(`shop`), 배송비(`post_price`), 등록월(`posted`), 카테고리 코드(`cate_ids`)를 함께 둔다.
- 광고 카드(`aria-label="상품명 N원"`)는 `source="ad_card"`로만 보관하고 판정에는 쓰지 않는다.

## 2. 검색 범위의 한계
- 검색 결과는 **한 번에 40개까지**, 인기순이다. 위쳐 3 검색은 게임 카테고리 집계가 90건인데 1페이지에는 일부만 온다. 2페이지 이후는 `dsearch.php?query=<검색어>&page=N`으로 받을 수 있다(시험 확인, robots.txt 허용). **기본 수집은 1페이지만 받는다.** 이유와 기준은 10절.
- **서버에 카테고리를 지정해 검색하는 방법은 없다.** `cate1`, `cate2`, `cate`, `cateName` 파라미터는 모두 무시된다(주소가 `/?query=`로 정리됨). 화면의 카테고리 탭은 `/api_ui/` 계열로 추정되며, robots.txt가 금지한 경로라 쓰지 않는다.
- 대신 받은 뒤 코드로 거른다(아래 3).
- 보강 검색: 기본 검색(`<이름>`)에서 개별 상품이 한 건도 통과하지 못한 IGDB 플랫폼만 `<이름> <플랫폼>`(예: `위쳐 3 스위치`)으로 추가 검색한다. 15개 후보에서 47건. 결과가 없으면 없는 것으로 기록한다(위쳐 3 Switch 2처럼).

## 3. 카테고리와 게임 판별
- 게임 대분류는 `cate_c1=1393`. 하위는 `200028`=콘솔게임, `1403`=PC/전용/에뮬레이터. 책(1841), 피규어(220348), 패션·잡화(1985) 등은 다른 대분류라 코드만으로 걸러진다.
- **카테고리는 부정확하다.**
  - 같은 Xbox 상품이 "PC게임"이나 "PS4-SW"에 달려 있다(사이버펑크 XBOX ONE 코드가 PS4 카테고리).
  - 실제 게임이 게임 카테고리 밖이다(`WHV GAMES [해외] … Xbox`가 c1=224).
  - 반대로 마우스패드·파우치·헤드셋이 게임 카테고리에 있기도 하다.
  - 카테고리 미지정(`0/0/0`)도 있다.
- 플랫폼 판정은 **번들명 → 카테고리 → 제목** 순. 개별 상품은 번들명이 없어 제목에 의존한다.
- 개별 상품의 `game_filter`:
  - `category`: 게임 카테고리(c1=1393) + 이름 일치 + 플랫폼 식별 + 비게임 키워드 없음. **가격 계산에는 이것만 쓴다.**
  - `title`: 카테고리는 게임이 아니지만 제목에 플랫폼과 이름이 있음. 가격에는 쓰지 않고 건수(`danawa_shop_matched_by_title`)만 센다. 책·피규어 중 제목에 플랫폼이 든 것이 섞여 들어오기 때문이다.
- 비게임 키워드: 아트북, 피규어, OST, 컨트롤러, 파우치, 케이스, 마우스패드, 장패드, 키보드, 매트, 액세서리, 키링, 스티커, 포스터, 공략, 가이드, Books, 헤드셋, 이어폰, 충전, 케이블, 모니터 등. 목록에 없는 상품은 통과한다.

## 4. 플랫폼 분류
- 규칙은 앞에서부터 먼저 맞는 것: Switch2 → Switch → PS5 → PS4 → XboxSeries → XboxOne → Xbox(세대 불명) → PC. Switch2가 Switch보다 앞에 있어야 한다.
- Xbox는 `XboxSeries`/`XboxOne`으로 나눈다. 세대 표기가 없으면 `Xbox`이고, 빈 플랫폼 판정에서는 두 세대를 모두 채운 것으로 본다.

## 5. 이름 매칭
- `names`(한글명·영문명·별칭)를 정규화(영숫자·한글만, 소문자)한 문자열이 제목에 포함되면 일치.
- 영문명 변형: 앞의 `The ` 제거, 앞부분에 숫자가 있을 때만 부제 제거(`The Witcher 3: Wild Hunt` → `Witcher 3`). `Monster Hunter: World`는 부제를 떼지 않는다.
- 같은 이름으로 시작하는 후속작·외전은 후보별 `danawa_exclude`로 거른다: 엘든 링→밤의 통치자, 갓 오브 워→라그나로크·라우페이, 하데스→하데스 2, 할로우 나이트→실크송.
- **IGDB 이름으로 별칭을 자동 생성한다**(`igdb_aliases`, CSV `igdb_aliases` 열, 원본은 `igdb/NN_names.json`).
  - 채택: 한국(Korea) 지역 이름, 한국어 약칭("사펑", "레데리2", "몬헌월드"), 영문 표기 변형(Witcher III, Helldivers II 등).
  - 제외: `.exe` 파일명, 한자·가나·키릴 등 한글·영문이 아닌 이름, 에디션 이름, 이론상·작업 중 제목, 5자 미만 영문 약어(RE4, GOW, TW3처럼 다른 제목에 섞일 위험).
  - 효과는 15개 후보에서 **통과 건수 변화 없음**이다. 다나와 상품명이 공식 한국어 이름을 쓰는 경우가 대부분이라 수동 이름만으로 이미 거의 다 잡혔다. 약칭을 쓰는 판매자 제목에 대한 안전망 성격이다.
- **불일치로 분류된 상품은 대부분 올바르게 걸러진 것이다.** 게임 카테고리인데 이름이 안 맞은 상품을 확인한 결과: 바이오하자드 4 → RE:2, RE7, 빌리지(다른 게임), 몬스터 헌터 월드 → 몬스터 헌터 와일즈, 할로우 나이트 → 컨트롤러 거치대, 사이버펑크 → 컨트롤러·콘솔 번들. 판매자가 이름을 줄여 쓴 경우("갓 워")는 드물다.
- 같은 게임의 **다른 버전**은 이름 매칭으로 구분되지 않는다. 바이오하자드 4는 2005년 원작·HD판이 "바이오하자드 4"로 달려 있어서, 수동 이름("바이오하자드 RE:4", "RE4")으로만 리메이크를 가려낸다.
- **이름 연결을 자동화하는 방법을 12~15절에서 시험했다. 요약**:

  | 방식 | 결과 | 용도 |
  |---|---|---|
  | IGDB 시리즈로 제외 이름 자동 생성(12절) | 수동 규칙 4개 후보에서 본편 오탐 0, 놓친 실제 상품 1건(`라우페이`) | 기본으로 쓴다. 규칙 대신 쓸 수 있음 |
  | 발음(자음 뼈대) 비교(13절) | 후보 상품 60% 재현, 짧은 이름은 불가, 제외에 쓰면 정상 에디션이 걸림 | 사람이 볼 항목 표시용만 |
  | LLM 한국어 표기 후보(14절) | Claude 89%, Gemini(눈가림) 86%. 잘못 거른 것 0. 공식 한국어 이름·철자 변형은 놓치고 엉뚱한 항목이 섞임 | 사람이 검수하는 후보 목록만 |
  | 시리즈 색인 후 배정(15절) | 자동 제외와 같은 결과, 충돌 0. 글자 수 점수는 한글·영문을 비교할 수 없음 | 엘든 링 색인 설계의 바탕 |

  - 결론: 제외 규칙은 **IGDB 자동 생성(+ 수동 예외)**, 별칭은 **IGDB 한국어 이름 + 검수한 LLM 표기**. 엘라스틱서치 도입 때는 배정 방식으로 옮기고 숫자 토큰 정확 일치·출시 연도를 색인에 넣는다. 배정(상품→게임 연결)은 정제 단계의 일이라 수집 쪽은 원본 상품명, IGDB 이름·시리즈 정보, 검수된 별칭 표를 저장하는 데까지로 본다(팀 확인 필요).

## 6. 본편/에디션
- `edition_tokens`(DLC, 골드, 얼티밋, GOTY, 컴플리트, 디럭스, 컬렉터즈, 리마스터, 마스터에디션, DAY1/2, 번들, 비게임 등)가 비어 있으면 `is_base`. 목록에 없는 표기는 본편으로 오분류될 수 있다.
- 가격 열(`danawa_{플랫폼}_{new,used}_krw`)은 **본편·국내판만**.
- 에디션은 버리지 않는다. `edition` 키(JSON)에 따로 두고, **본편 가격이 없는 (플랫폼, 상태) 칸에만** `danawa_edition_fallback`에 대체 값으로 표시한다. DLC·확장팩은 대체 후보에서 뺀다. 대체 값은 구성이 달라 본편과 직접 비교하면 안 된다.
- 본편 값이 있으면 더 싼 에디션이 있어도 대체 값이 붙지 않는다(위쳐 3 Switch는 대부분 컴플리트 에디션인데 카탈로그 본편 187,000원이 있어 에디션 가격은 JSON에만 남는다).

## 7. 해외판/수입
- `region_lang`이 `import`(해외구매·해외직구·`[해외]`·일본판·유럽판·아시아판·북미판·수입)면 국내 가격 열에서 뺀다.
- 해외판은 `danawa_import_items`, `danawa_import_prices`와 JSON의 `import`에 따로 둔다. 국내 상품이 없고 해외판만 있으면 `danawa_*_import_only=True`(할로우 나이트·스타듀 밸리 카탈로그).
- 표기 없는 해외 상품은 구분하지 못한다(`region_lang`이 비어 있음). 해외판을 최종적으로 제외할지는 미정.

## 8. 가격과 이상값 표시
- `minPrice`가 0이면 판매처가 없는 상품 → `None`, 최저가 계산에서 제외.
- 개별 판매처 상품의 가격은 배송비 제외. 배송비는 `post_price`에 따로.
- 이상값은 **값을 바꾸거나 빼지 않고 표시만** 한다(`danawa_price_flags`, 슬롯의 `flags`).
  - `single_source`: 그 칸에서 가격이 있는 상품이 1건뿐
  - `few_shops`: 최저가가 카탈로그 상품인데 판매처 2곳 미만
  - `new_vs_used`: 같은 플랫폼에서 신품이 중고의 3배 이상이거나 중고가 신품보다 비쌈
- 기준값(3배, 2곳)은 임의값이다. `single_source`가 후보 15개의 66칸 중 33칸에 붙어 "의심"보다 "근거가 약함"에 가깝다.
- `danawa_price_sources`에 칸별 출처(`catalog` / `shop_listing:판매처`)를 적는다.

## 9. 요청 규칙
- robots.txt는 `Crawl-delay: 10`을 선언한다. 스크립트는 `max(3초, crawl-delay)`로 요청한다. 모바일 검색(`/mobile/dsearch.php`)은 허용 경로지만 쓰지 않는다.
- 후보 15개 기준 기본 검색 15건 + 보강 검색 47건 ≈ 10분.
- 검색 결과 HTML은 Next.js 내장 데이터를 정규식으로 파싱한다. 구조가 바뀌면 `catalog` 항목이 0건이 되고 notes에 경고가 남는다.
- 정규식에 `\b`를 쓸 때는 raw 문자열(`r"..."`)로 쓴다. 일반 문자열이면 백스페이스 문자로 저장돼 규칙이 조용히 안 맞는다(실제로 겪음).

## 10. 검색 결과 2페이지 이후를 받을지 (결정과 근거)
### 왜 고려해야 하나
- 한 페이지는 40건이고 인기순이다. 검색 결과 전체 규모는 1페이지 응답에 들어 있다(`count.total`, `page.total`, `category.list`). 후보 15개의 규모는 **총 51건(2페이지)부터 4,350건(109페이지)까지** 차이가 크다.
- 게임 카테고리(1393) 건수 합계는 1,414건인데, 1페이지에서 본 게임 카테고리 항목은 242건(약 17%)이다. 게임별로 보면 하데스 3%, 할로우 나이트 2%, 갓 오브 워 6%만 본다. 놓친 가격이 있을 수 있다는 의심(사용자가 다나와 사이트에서 직접 더 싼 상품을 찾은 일)의 근거가 된다.
- 게임 카테고리 집계에는 게임주변기기(컨트롤러 등)가 섞여 있어(위쳐 3: 게임 90 = 콘솔 44 + PC 29 + 주변기기 17) 실제 게임 상품은 이보다 적다. 집계 숫자의 정확한 의미(그룹 수인지 상품 수인지)는 확인하지 못했다. 비율은 대략의 지표로만 쓴다.

### 시험한 것 (위쳐 3, 2026-11-19, 요청 2건: `page=2`, `page=3`)
| 페이지 | 항목 | 게임 카테고리 | 카탈로그 상품 | 이름 일치 새 항목 중 본편·국내판·가격 있음 |
|---|---|---|---|---|
| 1 | 49 | 19 (38%) | 13 | (기준) |
| 2 | 40 | 9 (22%) | 0 | **0건**. 해외판 본편 5건, 에디션 3건 |
| 3 | 42 | 23 (54%) | 17 | **0건**. DLC 묶음, 콘솔 본체 번들, 북미판, 판매처 없는 상품 |

- "뒤로 갈수록 게임 비중이 줄어든다"는 처음 추측은 **틀렸다.** 3페이지는 오히려 38%→22%→54%로 오르내린다. 비게임이 아니라 DLC·번들·해외판·에디션이 많다.
- 위쳐 3에서는 2·3페이지가 본편 국내판 가격을 바꾸지 못했다. 기본 검색에 이미 있는 값과 "빈 플랫폼 보강 검색"(`위쳐 3 스위치` 등)이 같은 일을 더 적은 요청으로 한다.
- 한계: **게임 하나, 3페이지까지만 확인했다.** 총 건수가 4,350건인 하데스나 1,938건인 할로우 나이트는 시험하지 않았다. 다른 게임에서도 같다고 단정할 수 없다.

### 결정
- **기본 수집은 1페이지 + 빈 플랫폼 보강 검색.** 2페이지 이후는 받지 않는다(15개 후보 × 2페이지 이상 ≈ 5분 이상, 비용 대비 본편 국내 가격을 바꾸지 못함).
- 대신 판단 근거를 매번 남긴다. CSV와 `*_parsed.json`의 `page_meta`에 기록한다.
  - `danawa_total_items`, `danawa_total_pages`: 전체 규모
  - `danawa_cat_game`, `danawa_cat_console`, `danawa_cat_pc`, `danawa_cat_accessory`: 카테고리별 건수
  - `danawa_pages_fetched`: 실제로 받은 페이지 수(현재 1)

- 지금은 구현하지 않았다. 필요하면 `--pages N` 옵션으로 추가한다(요청 수는 게임 수 × N × 10초).

### 결론
- **다나와 리뷰와 다나와 가격 이력(할인 이력)은 정적 HTML로는 받을 수 없다.** 화면이 열린 뒤 브라우저가 따로 불러오는 구조다.
- 불러오는 주소를 HTML에서 찾지 못했다. 이름으로 보아 `/info/ajax/`, `/community/`, `/api/` 쪽일 가능성이 높고(추정), 이 경로들은 robots.txt가 금지한다. 금지 경로는 **추측해서 호출하지 않는다.**
- 따라서 명세 ⑤(다나와 리뷰)와 다나와 "할인 이력"은 **현재 방식으로는 수집 불가**로 본다. 콘솔 가격 이력은 우리가 6시간마다 쌓는 스냅샷으로 만든다.
- **수집 가능한 것:** 상세 페이지의 판매처별 가격표(10개)는 콘솔 가격 비교(①)의 근거로 쓸 수 있다. 다만 검색 결과의 `minPrice`가 이미 최저가이므로, 얻는 것은 "판매처별 가격·배송비" 정도다.

### 확인이 필요한 것 (사용자 브라우저에서)
- 리뷰·차트가 어떤 주소에서 오는지 확인해야 robots.txt 허용 여부를 판단할 수 있다.
  1. 상세 페이지를 연다 → 개발자 도구(F12) → Network → Fetch/XHR 필터.
  2. 페이지를 새로고침하고 "의견/리뷰" 탭, 가격 추이 영역을 열어 본다.
  3. 새로 나타나는 요청의 주소(경로만)를 알려 준다.
- 주소가 `/api/`, `/community/`, `/info/ajax/`이면 금지 경로이므로 수집하지 않는다. 그 밖의 경로면 허용 여부를 robots.txt로 다시 판단한다.

### 사용자가 확인한 요청 목록 (2026-11-20, 호그와트 레거시 Switch 2 상세 페이지, Fetch/XHR)
화면이 열린 뒤 브라우저가 따로 부르는 요청이다. **호스트와 폴더가 없는 파일명뿐이라 robots.txt 허용 여부는 아직 판단하지 못했다.**

사용자가 Network 탭에서 복사한 전체 주소 5개를 `prod.danawa.com/robots.txt`(`Disallow: /api/`)로 `urllib.robotparser` 검사했다. **모두 금지.** 이 주소들은 호출하지 않았다.

- 공통점: 데이터 요청이 모두 `/api/proxy/` 아래라 `/api/` 금지 규칙에 걸린다. 상세 페이지 화면 데이터는 정적 HTML(판매처 가격표 등)과 이 `/api/` 호출로 나뉘는데, 리뷰·주제어·커뮤니티는 후자뿐이다.
- 가격 추이 차트가 어느 주소에서 오는지는 목록에 없었다(목록은 일부일 수 있다). 어쨌든 **다나와 가격 이력은 정적 HTML에 없다.**
- **결정: 다나와 리뷰·주제어·커뮤니티·할인 이력은 수집하지 않는다.** 공식 API나 제휴 데이터가 따로 있는지는 확인하지 못했다.
- 영향: 명세 ⑤의 "다나와 리뷰" 출처, 명세 ②·① 의 다나와 "할인 이력"은 그대로 구현할 수 없다. 콘솔 가격 이력은 우리가 쌓는 스냅샷으로 대체한다.

## 12. 제외 규칙 자동 생성 시험 (2026-11-20)
스크립트 `scripts/check_exclude_auto.py`, 결과 `samples/check_exclude_auto/`. 다나와 요청은 없고 IGDB만 호출했다. 저장된 다나와 결과 15건에 적용해 수동 `danawa_exclude`와 비교했다.

**방법**: 후보와 같은 시리즈(`collections`/`franchises`)와 같은 이름 검색 결과에서, 대표 이름이 후보와 다르고 이름(영문·대체 이름·한국어 현지화)에 후보 이름이 들어 있으며 더 긴 항목을 제외 이름으로 삼는다. 에디션·번들·DLC류(`game_type` 1,2,3,13,14)와 `version_parent`가 후보인 항목은 같은 게임으로 보고 뺀다(에디션은 `edition_tokens`가 따로 처리).

**보정한 점(시험 중 확인한 오탐)**
- 로마 숫자를 아라비아 숫자로 맞춘다. 안 맞추면 `하데스 II`와 `하데스2`를 못 잡는다.
- 숫자로 끝나는 이름 뒤에 숫자가 이어지면 일치로 보지 않는다. 안 막으면 `God of War 2018`이 `God of War 2`로 잡힌다.
- 대표 이름이 후보와 같은 항목은 제외하지 않는다. 대체 이름만 같은 항목까지 막으면 `God of War Ragnarök`을 놓친다.
- 이름 정규화는 공백·특수문자를 없앤다. 수동 규칙의 `밤의 통치자`는 공백이 있어야 맞지만 자동은 `엘든링밤의통치자`도 잡는다.

**결과(수동 규칙이 있던 4개)**
| 후보 | 수동∩자동 | 수동만 | 자동만 |
|---|---|---|---|
| 엘든 링 | 17 | 0 | 0 |
| 갓 오브 워 | 28 | 16 | 0 |
| 할로우 나이트 | 3 | 1 | 0 |
| 하데스 | 8 | 0 | 0 |
- 수동만 잡은 17건 중 16건은 컨트롤러 스탠드·스티커·피규어 같은 비게임 상품이다. `비게임` 토큰이 이미 거르므로 제외 규칙의 몫이 아니다.
- 진짜로 자동이 놓친 것은 `산타모니카 갓 오브 워: 라우페이` 1건(89,800원 카탈로그)이다. 다나와 쪽 표기가 IGDB 한국어 이름에 없다.
- 수동 규칙이 없던 11개는 자동 제외가 걸린 항목이 0건이다. 본편을 잘못 거른 사례는 없었다.

**한계**
- 다나와 제목은 한국어(또는 판매자가 쓴 영문)라, 제외 대상 시리즈 항목에 한국어 이름이 있어야 걸린다. 엘든 링은 14개 중 1개(나이트레인), 갓 오브 워는 32개 중 7개만 한국어 이름이 있다. 나머지는 영문 표기를 쓴 상품에만 걸린다.
- 같은 이름의 원작·리메이크(바이오하자드 4)는 이름만으로 구분할 수 없다. 이름 지정(`names`)을 유지해야 한다.
- 기기·컨트롤러 같은 비게임 키워드는 IGDB에서 나오지 않는다. 비게임 토큰 규칙을 계속 쓴다.
- 별칭 4건(헬다이버스 2, 백 포 블러드, 스타듀벨리, 잇 테이크 투) 중 헬다이버스 2와 잇 테이크 투는 IGDB 한국어 이름에서 자동 생성된다. 백 포 블러드(IGDB는 `Back for Blood`), 스타듀벨리(IGDB는 `스타듀 밸리`)는 판매자 표기라 자동으로 안 나온다.

**판단**: 제외 규칙은 자동 생성을 기본으로 쓰고, 자동이 못 거르는 건만 수동 예외로 둔다. 자동 규칙으로 바꾼 뒤 결과를 처음 한 번 사람이 확인한다.

## 13. 발음 기준 느슨한 이름 비교 시험 (2026-11-20)
스크립트 `scripts/check_phonetic_match.py`, 결과 `samples/check_phonetic/report.json`. 외부 호출 없이 저장된 샘플만 썼다.

**방법**: 영어 이름과 한글 상품명을 같은 '자음 뼈대'로 바꿔 편집 거리로 비교한다. 비슷한 자음을 합친다(b/p/f/v, d/t, g/k/c/q, l/r, s/z/ch/j). 영어에서는 모음을 버리고 모음 앞이 아닌 r도 버린다(cyber→사이버, Hogwarts→호그와트). 한글은 자모로 분해해 같은 규칙을 쓴다. 숫자는 정확히 맞아야 하고 로마 숫자는 아라비아 숫자로 바꾼다. 단어 시작 위치에서만 시작할 수 있다.

**3번 조정한 과정**
| 조정 | T1 재현율(영어 이름만으로 후보 상품 찾기) | T2 오탐(다른 후보 상품에 걸림) |
|---|---|---|
| 1차(철자 규칙 기본, 편집 거리 1) | 낮음(사이버펑크 6/56 등) | 83건 |
| 2차(r 탈락, s/c 합침, 짧은 뼈대는 정확 일치) | 높음 | 74건(뼈대가 3글자인 `갓 오브 워` 등이 아무 데나 걸림) |
| 3차(뼈대 4글자 미만 비교 안 함, 단어 시작에서만 시작) | 아래 | 1건 |

**3차 결과**: 15개 중 뼈대가 충분히 긴 이름은 대부분 영어 이름만으로 찾는다(엘든 링 85/85, 할로우 나이트 29/29, 스타듀 밸리 10/10, 사이버펑크 50/56 등). 한계는 다음과 같다.
- 뼈대가 3글자 이하인 이름은 비교할 수 없다(갓 오브 워 0/60, 하데스 0/42). 짧은 뼈대를 허용하면 오탐이 폭증한다.
- 철자 변형(백 포 블러드, 잇 테이크 투)과 발음이 먼 표기(레드 데드 리뎀션 2 1/19)는 놓친다. 바이오하자드처럼 영어 이름과 무관한 이름은 못 찾는다.
- 오탐은 1건(씨 오브 시브즈 ← 헬다이버즈 2 중고 상품).

**제외 이름에 쓰는 것(T3)**: 위험하다. `Elden Ring: Ascended`처럼 후보 이름에 짧은 꼬리만 붙은 항목이 `ELDEN RING SHADOW OF THE ERDTREE EDITION`(후보의 에디션)에 걸려 22건이 잘못 걸렸다. 반면 수동 규칙과 IGDB 한국어 이름이 둘 다 놓친 실제 상품 1건 `[해외] 엘든 링 나이트레인 PS5 스탠다드 에디션`을 찾았다(수동 규칙은 `밤의 통치자|nightreign`뿐이라 `나이트레인` 표기를 못 거름).

**판단**: 자동 판정에는 쓰지 않는다. 다음 용도로만 둔다.
- 이름이 걸린 항목을 "확인 필요"로 표시하고 사람이 본다(특히 제외 후보).
- 이름 연결에서 한국어 이름이 IGDB에 없는 후보의 후보 목록을 만들어 별칭 표에 넣을 때 보조로 쓴다.
- 뼈대가 4글자 미만인 이름은 쓰지 않는다.

## 14. LLM 한국어 표기 후보 시험 (2026-11-20)
스크립트 `scripts/check_llm_names.py`, 입력 `samples/check_llm_names/proposed.json`, 외부 호출 없음.

**방법**: 영어 이름만 보고 한국어 표기 변형을 적은 목록을 만들어(이 시험에서는 Claude가 직접 작성) 저장된 다나와 결과에 적용했다. 후보 자신의 이름과 시리즈 다른 게임의 이름 두 가지를 봤다.

**주의(결과 해석)**: 프로젝트 `.env`에는 LLM 키가 없고, 이번 시험은 API 호출이 아니다. 백 포 블러드, 스타듀벨리, 잇 테이크 투, 나이트레인 표기는 앞선 작업에서 다나와 표기를 이미 본 뒤라 완전한 눈가림이 아니다. 실제 수치는 이보다 낮을 수 있다.

**결과**
- 후보 자신의 이름: 한국어 변형만으로 487건 중 433건(89%)을 찾았다. 놓친 것은 판매자가 영어로 쓴 상품명이 대부분이고, 이것은 IGDB 영어 이름으로 이미 찾는다.
- 시리즈 다른 게임: 수동 규칙과 IGDB 자동 규칙이 둘 다 놓친 `엘든 링 나이트레인` 상품 5건을 찾았다(수동은 `밤의 통치자`, IGDB 한국어 이름도 `밤의 통치자`뿐이었다).
- 잘못 거른 상품은 없었다. 갓 오브 워, 할로우 나이트, 하데스는 추가로 찾은 것이 없고, 기존 규칙과 같은 결과다.
- 수동만 거른 항목은 컨트롤러 스탠드 같은 비게임 상품이며 `비게임` 토큰이 거른다.

**판단**
- 발음 비교(13절)와 달리 LLM 표기는 짧은 이름이나 철자 변형도 목록에 넣을 수 있고, 목록을 사람이 검수한 뒤 별칭 표로 저장하므로 오탐이 통제된다.
- 게임마다 한 번만 만들고 저장한다. 호출량은 게임 수에 비례하는 일회성이다.
- 실제로 쓰려면 LLM 키 관리(`.env`)와 검수 절차를 정해야 한다. 키가 없으면 `IGDB 한국어 이름(자동) + 수동 별칭(검수)`이 현재 최선이다.
- 시험을 눈가림으로 다시 하려면 다나와 표기를 보지 않은 새 후보 몇 개로 같은 시험을 해야 한다.

### 14-1. Gemini로 다시 시험 (눈가림, 2026-11-20)
스크립트 `scripts/gen_gemini_names.py`(생성), `scripts/check_llm_names.py gemini_proposed.json`(평가). 키는 `.env`의 `GEMINI_API_DANAWA_NAME_GENERATE_KEY`. 보낸 것은 영어 게임 이름(후보는 출시연도 포함)뿐이고 다나와 표기·가격은 보내지 않았다. 결과 `samples/check_llm_names/gemini_proposed.json`, 응답 원본 `gemini_raw.json`.

**모델**: `gemini-3.5-flash-lite`. `gemini-2.5-flash`는 신규 사용자에게 닫혀 있고, `gemini-3.8-flash`는 응답이 느리고, `gemini-3-flash-preview`는 호출 한도(429)에 걸렸다. 가벼운 모델이라 더 큰 모델은 결과가 더 좋을 수 있다.

**결과(앞의 Claude 작성 시험과 비교)**
| 항목 | Claude 작성(눈가림 아님) | Gemini(눈가림) |
|---|---|---|
| 후보 자신의 이름 찾기 | 433/487 (89%) | 420/487 (86%) |
| 나이트레인 상품(수동·IGDB 자동이 놓친 것) | 5건 | 5건 |
| 잘못 거른 상품 | 0 | 0 |
| 갓 오브 워 `라우페이` | 찾음 | 못 찾음 |
| 엘든 링 공식 한국어 이름 `밤의 통치자` | 영어·IGDB로 보완 | Gemini 목록에 없음 |

**Gemini 목록의 문제**
- 공식 한국어 이름을 모르고 음차로만 쓴다: 엘든 링 밤의 통치자, 갓 오브 워 라우페이를 못 만들었다.
- 철자 변형이 빠진다: 잇 테이크**스** 투(목록에는 `잇 테이크 투`만), 헬다이버스 2(목록에는 헬다이버즈), 스타듀벨리. 그만큼 후보 상품을 놓친다(잇 테이크스 투 19/37, 헬다이버즈 2 9/15).
- 엉뚱한 항목이 섞인다: `할로윈`(할로우 나이트), `하다스`, `해적게임`, `두명이서`, `엘든 링 DLC`, 짧은 `사이버펑크`·`호그와트`, 은어(`사펑`, `스듀`, `B4B`). 그대로 쓰면 오탐이 생긴다.

**판단**
- 사람이 검수하는 후보 목록으로만 쓴다. 자동 반영 금지.
- IGDB 한국어 이름과 합칠 때 효과가 가장 크다. Gemini는 `나이트레인` 같은 음차 변형을, IGDB는 공식 이름(`밤의 통치자`)을 채운다.
- 검수 전에 규칙으로 걸러낸다: 3글자 미만, 후보 이름 없이 일반 단어만 있는 표기, 은어.

## 15. 상품→게임 배정 시험 (2026-11-20)
스크립트 `scripts/check_assign.py`(외부 호출 없음). 수동 제외 규칙 없이 "후보와 같은 시리즈 게임을 함께 색인해 가장 잘 맞는 게임에 배정"하는 방식을 저장된 다나와 결과에 적용했다.

**방법**: 문서 = 후보 + 시리즈 다른 게임(IGDB). 점수 = 상품명에서 찾은 이름 키 중 가장 긴 것의 길이(엘라스틱서치의 "더 구체적으로 맞을수록 점수가 높다"를 단순화한 것). 가장 높은 문서에 배정하고 후보가 아닌 문서에 배정된 상품은 버린다. A는 IGDB 이름만, B는 IGDB + Gemini 표기(14-1절).

**결과(15개 후보, 상품 487건)**
| | A(IGDB만) | B(IGDB+Gemini) |
|---|---|---|
| 수동 규칙과 같이 버린 것 | 55 | 55 |
| 배정만 버린 것 | 0 | 5(엘든 링 나이트레인) |
| 수동만 버린 것 | 18 | 18 |
| 같은 점수 충돌 | 0 | 0 |
- 수동만 버린 18건: 갓 오브 워의 컨트롤러 스탠드·스티커 등 비게임 16건(비게임 토큰이 거름), `갓 오브 워: 라우페이` 1건, `하데스2 Hades with bonus` 1건.
- 수동 규칙이 없던 11개 후보에서 배정이 버린 상품은 0건이다. 본편을 잘못 버린 사례가 없다.

**알게 된 것**
- 결과는 5절의 자동 제외와 같다. "가장 긴 이름이 맞는 문서에 배정"은 "후보보다 긴 시리즈 이름은 제외"와 같은 논리라서다. 이 시험이 확인한 것은 수동 제외 규칙 없이도 같은 결과가 나온다는 점과 충돌이 없다는 점이다. 엘라스틱서치 점수(BM25, 분석기)의 효과는 시험하지 못했다.
- 점수를 글자 수로 재면 문자 종류가 다른 이름끼리 비교할 수 없다. `하데스2 Hades with bonus`에서 후보의 영어 이름 `Hades`(5글자)가 시리즈의 `하데스2`(4글자)를 이겨 하데스 2 상품이 후보에 붙는다. 엘라스틱서치에서는 분석기로 토큰을 나누고 한글·영문 이름에 같은 필드 기준을 쓰거나, 숫자 토큰 일치에 가중치를 주는 식의 보정이 필요하다.
- 원작과 리메이크가 같은 이름인 항목(바이오하자드 4 등)은 이름만으로는 배정할 수 없다. 출시 연도나 플랫폼 정보가 색인에 있어야 한다.

**엘라스틱서치 색인 설계 메모**
- 문서 필드: `igdb_id`, `name_en`, `names_ko`(IGDB 한국어 + 검수된 별칭), `aliases`, `series_ids`, `first_release_year`, `game_type`, `is_candidate`.
- 질의: 다나와 상품명. 점수가 가장 높은 문서가 후보가 아니면 버리고, 1등과 2등의 점수 차가 작으면 "확인 필요".
- 숫자는 별도 토큰으로 정확히 일치시킨다(`2`와 `2018` 구분).
- 비게임 상품(컨트롤러·스티커 등)은 색인과 별개로 비게임 규칙이 먼저 거른다.
