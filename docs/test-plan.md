# 전체 흐름 테스트 계획 (게임 10개)

> 본 수집 전에 **수집 → 정제 → DB**가 끝까지 이어지는지 확인한다. 기간 11/20(금) ~ 11/23(월) 오전.
> 원칙: Kafka 없이 먼저 끝까지 잇고(1~5), 마지막에 Kafka를 끼운다(6~7). 문제가 어느 단계에서 생겼는지 바로 알 수 있다.

## 넘겨주기
```
11/20 저녁  한예찬 → 이고은 : 샘플 JSON + 필드 매핑표
11/20 저녁  김준영 → 전원   : VM·DB 접속 정보
11/20 저녁  남현식 → 전원   : Kafka 주소, 토픽 목록
11/21 오전  이고은 → 김준영 : 확정 ERD (테이블 생성)
11/21 오후  이고은 → 김준영 : 정제 결과 JSON (직접 적재)
11/22       한예찬 + 이고은 → 남현식 : Producer·정제 Kafka 연결
11/23 오전  김준영 → 전원   : 검증 결과 → 통과하면 본 수집 시작
```

## 통과 기준 (8단계)
- [ ] 수집 건수 = raw 토픽 메시지 수
- [ ] raw → refined 게임 ID 매칭률 90% 이상, 실패 건은 `refined.unmatched`에 목록으로
- [ ] refined 메시지 수 = MariaDB 행 수 (5단계 직접 적재 결과와도 같음)
- [ ] 같은 데이터를 한 번 더 돌려도 DB에 중복 행 없음 (upsert)
- [ ] MongoDB에 raw 원본이 모두 있음
- [ ] 확인 쿼리: 게임별 최저가 스토어, 가격 이력 건수, 사양 텍스트 존재 여부

## 막혔을 때
- 1~2단계가 늦으면 ITAD·IGDB 두 출처로 먼저 넘기고 Steam·다나와는 뒤에 붙인다.
- 3~4단계(이고은)가 막히면 ERD는 김준영, 다나와 정제는 한예찬이 이어받는다.
- 남현식의 작업은 Kafka VM(kafka1~3)에서 한다. 컨테이너는 쓰지 않는다.
