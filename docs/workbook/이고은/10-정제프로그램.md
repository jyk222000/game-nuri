# 10. 정제 프로그램 refiner (raw.* → refined.*)

`raw.*` 토픽의 원본을 읽어 정제한 뒤 `refined.*` 토픽으로 보냅니다. 코드는 `pipeline/refiner/`이고, 메시지의 `kind` 값으로 어떤 규칙을 쓸지 고릅니다.

## 10-1. 구상: 무엇을 어떻게 정제하나
| 들어오는 것 (토픽 / kind) | 규칙 파일 | 나가는 것 |
|---|---|---|
| `raw.price` / `price` (ITAD 가격) | `rules/price.py` | `refined.prices` |
| `raw.igdb` / `game_info` | `rules/game.py` | `refined.games` + 연결 토픽 14개 |
| `raw.steam` / `app_details` | `rules/requirements.py` | `refined.requirements` |
| `raw.console` / `console_price` (다나와) | `rules/console.py` | `refined.prices` |
| 리뷰·동접 등 그 밖의 kind | (규칙 없음) | 건너뜀 (리뷰는 Connect가 따로 저장) |
| 매칭 실패·깨진 메시지 | - | `refined.unmatched` (버리지 않고 기록) |

### 정제 규칙
| 대상 | 규칙 |
|---|---|
| 빈 값·날짜 | 빈 값은 `NULL`. 날짜는 `YYYY-MM-DD`, 시각은 UTC 문자열 그대로 (DATETIME 변환은 Connect가 한다) |
| 가격 | KRW는 그대로, USD·EUR·GBP는 환율을 곱해 원화로. `price_original`, `currency_original`은 항상 채운다. 환율은 임시 고정값(USD 1400, EUR 1500, GBP 1800) |
| 중복 | 같은 (game_id, store, edition, platform, item_condition)은 낮은 가격 한 줄. ITAD 가격은 `PC`·`new` |
| 게임 | 서비스 대상 플랫폼(PC, PS4, PS5, Switch, Switch2, XboxOne, XboxSeries)만 남기고 Mac 등은 뺀다 |
| 사양 | Steam HTML을 `OS / CPU / RAM / GPU` 텍스트로. 사양이 없으면 행을 만들지 않는다 |
| 멱등성 | 같은 메시지를 두 번 처리해도 결과가 같다. 출력 형식은 `docs/contracts/messages/refined.*.json` |
| 메시지 키 | 가격 `game_id:store:edition:platform:item_condition`, 게임·사양 `game_id` |

### 다나와(콘솔) 가격 규칙
| 상황 | 처리 |
|---|---|
| 상품명 매칭 | 이름을 정규화해 게임 이름·별칭(`game_aliases`)과 정확히 일치할 때만 게임에 붙인다. 못 붙이면 `unmatched` |
| 플랫폼·상태 | `platform_hint`, 없으면 상품명에서 찾고 못 찾으면 `unmatched`. 신품·중고는 `item_condition` |
| 본편 상품이 없는 플랫폼 | 에디션 가격을 쓰고 상품 이름을 `variant_name`에 담는다 |
| 신품 정가·할인율 | 출시가를 정가(`regular_krw`)로 쓰고 할인율(`discount_pct`)을 계산한다. 중고는 비운다 |

### 한 게임이 여러 행이 되는 토픽 14개 (`rules/links.py`)
| 토픽 | 테이블 / 출처 |
|---|---|
| `refined.genres`, `game_genres` | genres, game_genres / IGDB genres |
| `refined.companies`, `game_companies` | companies, game_companies / 개발·배급 |
| `refined.tags`, `game_tags` | tags, game_tags / IGDB themes, keywords |
| `refined.game_series`, `game_series_map` | game_series, game_series_map / collections, franchises |
| `refined.game_platforms` | game_platforms / platforms + 플랫폼별 출시일 |
| `refined.game_aliases` | game_aliases / 이름, 한글 이름, 대체 이름 |
| `refined.game_store_ids` | game_store_ids / Steam appid, ITAD id, 다나와 pcode |
| `refined.time_to_beat`, `player_counts`, `exchange_rates` | game_time_to_beat, player_counts, exchange_rates |

## 10-2. 게임 ID 통합 (`id_map.json`)
가격·사양 메시지에는 IGDB ID가 없어서, ITAD id·Steam appid·정규화한 상품명을 IGDB ID로 바꾸는 대응표가 필요합니다.
| 방법 | 설명 |
|---|---|
| 시작 대응표 | 게임 목록 CSV(열: `igdb_id, steam_appid, itad_id, name, name_ko, aliases`)로 만든다. 주로 이것을 쓴다 |
| 스스로 배우기 | `raw.igdb`를 받으면 Steam appid·게임 이름을, ITAD 가격에 Steam appid 힌트가 있으면 ITAD id를 배운다. `ID_MAP_STATE_PATH`에 저장해 재시작해도 남는다 |

```
# 서버 이름 확인
[adminc@kafka1 ~]$ hostname

# pipeline 폴더로 이동해서 가상환경을 켠다
[adminc@kafka1 ~]$ cd /opt/game-nuri/repo/pipeline && source ../.venv/bin/activate

# 게임 목록 CSV 로 시작 대응표를 만든다. --base 로 기존 대응표 위에 합친다
# 배우기는 서버마다 따로라서, 정제 결과가 서버마다 달라지지 않게 이 시작 대응표를 주로 쓴다
(.venv) [adminc@kafka1 pipeline]$ python -m refiner.build_id_map --csv games.csv --out refiner/id_map.json --base refiner/id_map.json
```

## 10-3. 서버 환경
| 항목 | 값 |
|---|---|
| 서버 | kafka1~3. 같은 consumer group(`refiner`)이라 세 대가 파티션을 나눠 받는다 |
| 실행 방식 | 컨테이너 없이 venv + systemd |
| 코드 위치 | `/opt/game-nuri/repo` |
| 가상환경 | `/opt/game-nuri/repo/.venv` (`pip install -r pipeline/requirements.txt -e shared`) |
| 필요 패키지 | confluent-kafka, requests, rapidfuzz |
| 환경 파일 | `/etc/game-nuri/refiner.env` (root:refiner, 640, 비밀번호 없음) |
| 서비스 정의 | `infra/kafka/systemd/refiner.service` (User=refiner, 실패하면 10초 뒤 재시작) |

```
# 환경 파일을 확인한다. 비밀번호는 들어 있지 않다. KAFKA_BOOTSTRAP, ID_MAP_PATH, ID_MAP_STATE_PATH 가 있어야 한다
[adminc@kafka1 ~]$ sudo cat /etc/game-nuri/refiner.env

# 서비스가 켜져 있는지 확인한다
[adminc@kafka1 ~]$ sudo systemctl status refiner
```

## 10-4. 새 코드를 서버에 반영하고 다시 시작
```
# 서버 이름 확인
[adminc@kafka1 ~]$ hostname

# 새 코드를 받는다. 서버 레포의 git 에는 sudo 를 붙이지 않는다 (붙이면 .git 이 root 소유가 되어 다음 git fetch 가 막힌다)
[adminc@kafka1 ~]$ cd /opt/game-nuri/repo && git pull

# refiner 를 다시 시작한다. 새 코드는 시작할 때 읽는다
# kafka1~3 이 파티션을 나눠 받으므로 세 대 모두 같은 순서로 해야 같은 규칙으로 정제된다
[adminc@kafka1 ~]$ sudo systemctl restart refiner

# 켜졌는지 확인한다
[adminc@kafka1 ~]$ sudo systemctl is-active refiner

# 로그에 오류가 없는지 본다 (Ctrl+C 로 빠져나온다)
[adminc@kafka1 ~]$ sudo journalctl -u refiner -f
```
