# 12. 정제 프로그램 코드 해설 (pipeline/refiner)

10번 문서가 "무엇을 정제하나"였다면, 이 문서는 **코드가 어떤 순서로 돌고 줄마다 무슨 일을 하는지**를 설명합니다.
아래 코드는 `pipeline/refiner/`의 실제 코드에서 핵심만 뽑고, `#` 주석을 붙인 것입니다(줄 수를 줄이려고 일부 생략, 생략은 `...`로 표시).
실제 파일은 레포에 있고, 이 문서의 주석은 설명용입니다.

## 12-1. 파일 구성과 호출 순서
| 파일 | 역할 | Kafka 필요 |
|---|---|---|
| `main.py` | Kafka에서 메시지를 읽고(소비), 정제 결과를 보내고(발행), offset을 저장(commit)하는 **반복문** | 필요 (서버에서만) |
| `router.py` | 메시지의 `kind`를 보고 어떤 규칙을 쓸지 고르는 **분배기** + 게임 ID 대응표(`Maps`) | 필요 없음 |
| `rules/price.py` | ITAD 가격 → `refined.prices` (원화 환산, 스토어 코드, 중복 제거) | 필요 없음 |
| `rules/price_change.py` | 가격이 **바뀐 때만** `price_history`로 보내려고 지난 가격을 기억 | 필요 없음 |
| `rules/game.py`, `links.py` | IGDB 게임 정보 → `refined.games` + 장르·회사·태그 등 연결 토픽 | 필요 없음 |
| `rules/requirements.py` | Steam 사양 HTML → 텍스트 | 필요 없음 |
| `rules/console.py`, `danawa_match.py` | 다나와 가격 → `refined.prices` (상품명을 게임에 연결) | 필요 없음 |

> <- **규칙 파일은 모두 "순수 함수"**입니다. 같은 입력이면 항상 같은 출력이고, Kafka·DB·시계를 쓰지 않습니다.
> 그래서 내 PC에서 `pytest`로 시험할 수 있고(`pipeline/tests`, 140개), 같은 메시지가 두 번 와도 결과가 같습니다(멱등).

```
raw.* 토픽 ──▶ main.py(반복문) ──▶ router.route(봉투)
                                      │ kind 로 분기
                                      ├─ price / console_price ─▶ price.py / console.py ─▶ refined.prices (+ price_history)
                                      ├─ game_info             ─▶ game.py + links.py      ─▶ refined.games + 연결 토픽
                                      ├─ app_details           ─▶ requirements.py         ─▶ refined.requirements
                                      └─ 그 밖의 kind          ─▶ 건너뜀(ignored)
                                      실패·매칭 못 함          ─▶ refined.unmatched
```

## 12-2. main.py : Kafka 모드 반복문
```python
# --- 소비자(Consumer) 만들기 ---
consumer = Consumer({
    "bootstrap.servers": bootstrap,       # kafka1:9092,kafka2:9092,kafka3:9092 (환경변수 KAFKA_BOOTSTRAP)
    "group.id": "refiner",                # 같은 그룹 이름 = kafka1~3 세 대가 파티션을 나눠 맡는다
    "enable.auto.commit": False,          # 자동 저장을 끈다. 아래에서 "발행이 끝난 뒤"에 직접 저장한다
    "auto.offset.reset": "earliest",      # 저장된 위치가 없으면(처음 켤 때) 맨 처음부터 읽는다
})

# --- 생산자(Producer) 만들기 ---
producer = Producer({
    "bootstrap.servers": bootstrap,
    "acks": "all",                        # 복제본 전체(min.insync.replicas=2 이상)가 받아야 성공으로 친다
    "enable.idempotence": True,           # 재전송해도 한 번만 쌓이게 한다(생산자 쪽 중복 방지)
    "delivery.timeout.ms": 300000,        # 브로커가 잠깐 끊겨도 5분까지 기다렸다 다시 보낸다
})
consumer.subscribe(t["in"])               # raw.price, raw.console, raw.igdb, raw.steam

while True:
    msg = consumer.poll(1.0)              # 메시지 1개를 꺼낸다(1초 기다려도 없으면 None)
    if msg is None:
        continue
    if msg.error():                       # Kafka 쪽 오류는 로그만 남기고 계속 간다
        log.error("consume error: %s", msg.error())
        continue

    try:
        res = route(json.loads(msg.value()), maps)   # 정제는 전부 router 가 한다
    except (ValueError, TypeError, KeyError) as e:
        # 깨진 메시지 하나 때문에 프로그램이 멈추면 안 된다 → 이유를 적어 unmatched 로 보낸다
        res = {"out": [], "ignored": False, "extras": {},
               "unmatched": [{"reason": f"메시지 해석 실패: {e}", "source": msg.topic(), "key": ...}]}

    for name, key, value in res["out"]:   # 정제 결과를 refined.* 토픽으로 발행
        producer.produce(t[name], key=key, value=json.dumps(value, ensure_ascii=False))
    for u in res["unmatched"]:            # 매칭 실패는 버리지 않고 refined.unmatched 로
        producer.produce(t["unmatched"], key=str(u.get("key")), value=json.dumps(u, ensure_ascii=False))

    producer.flush()                      # 1) 발행이 끝날 때까지 기다린다
    save_maps(maps, state_path)           # 2) 새로 배운 대응표를 파일에 저장(재시작해도 남게)
    maps.last_prices.save(os.environ.get("PRICE_STATE_PATH"))   # 3) 지난 가격도 저장
    consumer.commit(msg)                  # 4) 맨 마지막에 offset 저장 (이 순서가 중요)
```
> <- **왜 commit을 맨 마지막에 하나요?** 발행 전에 프로그램이 죽으면, offset이 저장되지 않아 재시작 때 **같은 메시지를 다시** 처리합니다.
> 한 번도 처리 못 하는 것보다 두 번 처리되는 편이 안전해서 "최소 한 번 처리(at-least-once)"를 택했고, 그래서 같은 메시지를 두 번 처리해도 결과가 같게(멱등) 만들었습니다.
> <- **메시지를 1개씩** 처리하고 매번 `flush`합니다. 느리지만 순서·복구가 단순해서 이 규모(수만 건)에서는 충분합니다.

## 12-3. router.py : kind 로 규칙 고르기
```python
def route(envelope, maps):
    kind = envelope.get("kind")           # 수집기가 붙인 메시지 종류. 분기는 kind 하나만 본다(source 는 쓰지 않는다)
    out, unmatched, extras = [], [], {}   # 보낼 것 / 못 맞춘 것 / 보내지 않고 대응표 학습에만 쓸 것

    if kind in ("price", "console_price"):
        if kind == "price":               # ITAD(PC 스토어) 가격
            hint = steam_hint(envelope)   # 수집기가 조회에 쓴 Steam appid 를 찾는다 (ITAD id → 게임 연결의 열쇠)
            # 가격 줄들을 만든다. ITAD id 를 게임 ID 로 바꾸는 함수와 그 달 환율표를 같이 넘긴다
            rows, unmatched = price_rules.refine_price(
                envelope, lambda i: maps.resolve_itad(i, hint), maps.rates.rates_for(day))
            # ... 새로 연결된 ITAD id 는 game_store_ids 로, 쓴 환율은 exchange_rates 로, 판매처는 stores 로도 보낸다
        else:                             # 다나와(콘솔) 가격
            rows, unmatched = console.refine_console_price(envelope, maps.alias.get, ...)
            kept = [r for r in rows if maps.last_prices.console_keep(r)]   # 본편이 있으면 에디션은 뺀다 (#93)
            rows = kept

        # 가격 줄 → refined.prices (현재 가격, 같은 키는 upsert 라 덮어쓴다)
        out = [("prices", price_rules.message_key(r), price_rules.to_connect_message(r)) for r in rows] + out
        # 처음 본 가격이거나 지난번과 달라졌을 때만 → refined.price_history (이력은 insert 라 쌓이기만 한다)
        out += [("price_history", ..., ...) for r in rows if maps.last_prices.is_new(r)]

    elif kind == "game_info":             # IGDB 게임 정보
        rows, extras, unmatched = game.refine_game(envelope)
        for r in rows:
            maps.learn_from_game(r, extras)                  # 이 게임의 Steam appid·이름을 대응표에 배운다
            out.append(("games", game.message_key(r), game.to_connect_message(r)))
            out += links.game_links(r, extras, payload)      # 장르·회사·태그·시리즈·플랫폼 등 연결 토픽 14개

    elif kind == "app_details":           # Steam 상세(사양)
        rows, unmatched = requirements.refine_requirements(envelope, maps.steam.get)
        # ... refined.requirements + Steam 파생 컬럼(refined.games_steam)

    else:                                 # review, owned_games 등: 정제 규칙이 아직 없다
        return {"out": [], "unmatched": [], "extras": {}, "ignored": True}
    return {"out": out, "unmatched": unmatched, "extras": extras, "ignored": False}
```
> <- 반환값의 `out`은 `(토픽 이름, 메시지 키, 메시지)` 목록입니다. 토픽에 실제로 쓰는 일은 `main.py`만 합니다. 그래서 router는 Kafka 없이 시험할 수 있습니다.

## 12-4. 게임 ID 통합 : Maps 클래스
가격 메시지에는 IGDB ID가 없습니다(ITAD id, 다나와 상품명뿐). 그래서 **대응표**로 IGDB ID를 찾습니다.
```python
class Maps:
    # itad  : {ITAD id(uuid)  : IGDB game_id}
    # steam : {Steam appid    : IGDB game_id}
    # alias : {정규화한 상품명 : IGDB game_id}
    def _put(self, table, key, game_id):
        # 이미 있는 값은 덮어쓰지 않는다. 먼저 알게 된 연결(시작 대응표)이 우선이고, 충돌로 잘못 바뀌는 것을 막는다
        if key in (None, "") or key in table:
            return
        table[key] = game_id
        self.changed = True               # main 이 이 값을 보고 상태 파일에 저장한다

    def resolve_itad(self, itad_id, steam_hint):
        if itad_id and itad_id in self.itad:        # 1순위: 이미 아는 ITAD id
            return self.itad[itad_id]
        gid = self.steam.get(steam_hint)            # 2순위: 가격 메시지의 Steam appid 힌트
        if gid is not None and itad_id:
            self._put(self.itad, itad_id, gid)      # 찾았으면 ITAD id 도 배워 둔다(다음엔 1순위로 바로 찾는다)
        return gid                                  # 못 찾으면 None → 호출한 쪽이 unmatched 로 보낸다
```
| 순서 | 방법 | 언제 |
|---|---|---|
| ① | 시작 대응표(`id_map.json`) | 서버 시작 때 읽는다 |
| ② | Steam appid 힌트 | 가격 메시지에 Steam appid가 있을 때 |
| ③ | 상품명 별칭 | 다나와처럼 ID가 없을 때, 이름을 정규화(`normalize_title`)해서 별칭표와 맞춘다 |
| ④ | 검색 게임 힌트 | 다나와 수집 때 검색한 게임. 검색어가 상품명 안에 있을 때만 |
> <- 못 찾으면 버리지 않고 `refined.unmatched`에 **이유와 함께** 보냅니다. unmatched 건수가 ID 통합이 얼마나 잘 되는지의 지표입니다.
> <- **주의:** 배운 대응표는 서버마다 따로 저장됩니다(`ID_MAP_STATE_PATH`). kafka1~3이 파티션을 나눠 받으면 게임 정보를 받은 서버와 가격을 받은 서버가 다를 수 있어서, 시작 대응표를 주로 쓰도록 했습니다.

## 12-5. rules/price.py : ITAD 가격 정제

```python
DEFAULT_RATES = {"KRW": 1.0, "USD": 1400.0, "EUR": 1500.0, "GBP": 1800.0}

def to_krw(amount, currency, rates):
    # 금액이 없거나 모르는 통화면 None → 호출한 쪽이 unmatched 로 보낸다. 0 으로 채우지 않는다

        return None
    return int(round(amount * rates[currency]))   # 원화는 항상 정수 (팀 규칙: price_krw 는 INT)

def store_code(shop):
    # ITAD 판매처 → 우리 store 코드. 번호로 먼저 찾고(Steam=61), 다음은 이름 규칙(epic, gog …)
    # 그래도 없으면 이름을 소문자 영숫자로 붙인다 (Humble Store → humblestore)

def refine_price(envelope, resolve_game_id, rates):
    payload = envelope["payload"]
    game_id = resolve_game_id(payload["id"])          # ITAD id → IGDB ID (위의 Maps.resolve_itad)
    if game_id is None:                               # 못 찾으면 가격은 만들지 않고 unmatched 사유만 돌려준다
        return [], [{"reason": "itad_id → IGDB ID 매칭 실패", "key": payload["id"], ...}]

    for deal in payload["deals"]:                     # 스토어마다 가격 한 줄(deal)이 온다
        price_krw = to_krw(deal["price"]["amount"], deal["price"]["currency"], rates)
        if price_krw is None:                         # 가격이 없거나 모르는 통화 → 그 줄만 unmatched
            continue
        rows.append({
            "game_id": game_id, "store": store_code(deal["shop"]),
            "edition": "digital", "platform": "PC", "item_condition": "new",   # ITAD 는 PC 디지털 신품만 다룬다
            "price_krw": price_krw,                                            # 원화 환산 값(정수)
            "price_original": deal["price"]["amount"],                         # 원래 금액
            "currency_original": deal["price"]["currency"],                    # 원래 통화 (항상 채운다)
            "collected_at": envelope["collected_at"],                          # UTC ISO 8601 문자열 그대로
            ...})
    return dedupe_by_key(rows), unmatched             # 같은 키는 낮은 가격 한 줄만 남긴다

def message_key(row):
    # Kafka 메시지 키 = game_id:store:edition:platform:item_condition  (prices_current 의 PK 와 같다)
    return ":".join(str(v) for v in price_key(row))
```
> <- 시각(`collected_at`)을 정제 프로그램이 새로 만들지 않고 수집기가 붙인 값을 그대로 씁니다. 같은 입력 → 같은 출력(멱등)을 지키려는 것입니다.
> <- 출력은 `{"schema": ..., "payload": ...}` 모양(JSON+schema)입니다. JDBC Sink가 컬럼 타입을 알아야 해서 schema를 같이 보냅니다.

## 12-6. rules/price_change.py : 가격이 바뀐 때만 이력
```python
class LastPrices:
    def is_new(self, row):
        key = ":".join(str(v) for v in price_key(row))   # prices_current 의 PK 와 같은 키
        sig = _sig(row)       # 비교 값 = [원래 통화 가격, 통화, 정가, 에디션 이름]
        if self.last.get(key) == sig:
            return False      # 지난번과 같으면 이력에 쌓지 않는다 → price_history 가 불어나지 않는다
        self.last[key] = sig  # 처음 보거나 달라졌으면 기억하고 True (이력의 첫 점도 포함)
        self.changed = True
        return True
```
> <- 비교에 `price_krw`(환산 값)를 쓰지 않는 이유: 환율이 달마다 바뀌어서, 원래 가격이 그대로여도 원화 값이 달라지기 때문입니다.
> <- 지난 가격은 `PRICE_STATE_PATH` 파일에 저장해 재시작해도 이어집니다. 파일이 없으면 재시작 뒤 첫 가격이 이력에 한 번 더 들어갑니다.

## 12-7. rules/requirements.py : Steam 사양 HTML → 텍스트
```python
LABEL = {"운영 체제": "OS", "프로세서": "CPU", "메모리": "RAM", "그래픽": "GPU", "저장 공간": "Storage", ...}

def html_to_text(html):
    if not isinstance(html, str) or not html.strip():
        return None                                   # 빈 값은 NULL (사양이 없으면 행도 만들지 않는다)
    text = re.sub(r"<br\s*/?>|</li>", "\n", html)     # 줄바꿈 태그를 줄바꿈으로
    text = re.sub(r"<[^>]+>", "", text)               # 나머지 HTML 태그는 지운다
    parts = []
    for line in text.split("\n"):
        m = re.match(r"\s*([^:]+?)\s*\*?\s*:\s*(.+)", line)       # "항목: 값" 모양만 뽑는다
        if m and m.group(1).strip() in LABEL:                      # 아는 항목(OS·CPU·RAM·GPU …)만 남긴다
            parts.append(f"{LABEL[m.group(1).strip()]}: {m.group(2).strip()}")
    return " / ".join(parts) or None                  # "OS: … / CPU: … / RAM: … / GPU: …"
```
