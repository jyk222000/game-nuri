# 다나와 크롤러

> 작성 2026-11-23 · 담당 한예찬 · 코드: `collector/collector/sources/danawa.py`, 시험: `collector/tests/test_danawa.py`
> 시험·규칙 근거는 `docs/collector-test/danawa-notes.md`. 키는 필요 없다.

## 하는 일
콘솔 플랫폼이 있는 게임마다 검색어로 `search.danawa.com/dsearch.php` **1페이지**를 받아, 검색 결과에 내장된 Next.js 데이터에서 **카탈로그 상품**을 읽어 `raw.console`로 보낸다.

| 항목 | 값 |
|---|---|
| 대상 | `games_1000.csv` 중 콘솔 플랫폼(PS5·PS4·Switch·Switch2·XboxSeries·XboxOne)이 있는 **794건** |
| 검색어 | 한글 이름(`name_ko`), 없으면 영문 이름 (한글 이름이 없는 게임 443건은 영문으로 검색) |
| kind / 키 | `console_price` / `pcode` |
| 단위 | 상품 1건 = 봉투 1개 |
| 소요 | 요청 1건 약 10~11초 → 794건 약 **2.3시간** (6시간 주기 안) |

payload = 계약(`raw.console.json`) 필드 `pcode`, `product_name`, `platform_hint`, `edition`, `lowest_price`, `shop_count`, `url` + 정제기가 읽는 `condition`(new/used), `medium`(disc/cartridge/code) + 원문 보조 필드 `bundle_name`, `category`, `release_price_text`.
`request.params`에 `query`와 `igdb_id`(검색한 게임)를 넣는다. 지금 정제기는 쓰지 않지만 매칭 근거로 남긴다.

## 보내는 것 / 안 보내는 것
수집기는 정제하지 않지만, 검색 결과의 노이즈는 보내지 않는다. 개수는 실행 끝에 로그로 남긴다.

| 구분 | 처리 |
|---|---|
| 카테고리 대분류가 "게임"이고 최저가가 있는 카탈로그 상품 | **보낸다** |
| 게임이 아닌 카테고리(주변기기·책 등) | 안 보냄 (`non_game`) |
| 최저가 0(판매처 없음) | 안 보냄 (`no_price`) — 정제기도 "가격 없음"으로 거른다 |
| 같은 실행에서 이미 보낸 pcode | 안 보냄 |
| 개별 판매처 상품(`TH201_…`), 광고 카드 | 이번 범위에서 뺌 |

## 지키는 규칙
- 시작할 때 `robots.txt`를 읽는다. 못 읽으면 중단한다. 금지 경로는 요청하지 않는다 (`/api/`, `/bridge/` 등은 아예 부르지 않고, 검색 페이지만 받는다).
- 요청 간격은 `max(10초, robots Crawl-delay)`. 429·5xx는 `Retry-After` 또는 30·60·120초 간격으로 최대 3회 재시도.
- User-Agent에 프로젝트명(`game-nuri-collector`)이 들어 있다.
- 검색 한 건이 실패하면 그 검색만 건너뛰고 계속한다. 검색 결과가 0건이면 경고(구조 변경 의심)를 남기고 계속하며, 검색의 절반 이상이 0건이면 오류 로그를 남긴다.

## 실행
```bash
PYTHONPATH=collector python -m collector.main --source danawa --dry-run --limit 2   # 약 25초
PYTHONPATH=collector python -m collector.main --source danawa                       # 약 2.3시간
```
> `collector/CLAUDE.md`는 간격을 `DANAWA_REQUEST_DELAY_SEC`로 조정한다고 적었지만 `shared`의 Settings에는 없다. 지금은 코드 상수(10초)와 robots 값으로 정한다. 설정으로 빼려면 `shared/` 변경(별도 PR)이 필요하다.

## 한글 이름이 없는 게임의 영문 검색 측정 (2026-11-23, 표본 30건)
다나와 대상 794건 중 CSV에 한글 이름이 없는 339건에서 순위 순으로 고르게 30건을 영문 이름으로 검색했다.
(IGDB `alternative_names`에 한국어 이름이 있는 게임은 이 339건 중 3건뿐이라 검색어 보강 효과가 거의 없다. Steam `l=koreana` 이름도 영문이다.)

| 결과 | 건수 | 비율 | 예 |
|---|---|---|---|
| 검색 결과 0건 | 18 | 60% | Brotato, Buckshot Roulette, Gorogoa, Pico Park, Hyper Light Drifter, Rogue Legacy |
| 결과는 있으나 게임 상품 없음 (흔한 단어) | 4 | 13% | Soma, Gris, Prototype, 60 Seconds! |
| 맞는 게임 상품이 나옴 | 5 | 17% | Pragmata(프래그마타), Cities: Skylines II, Forza Horizon 6, Call of Duty: Infinite Warfare, Deathloop |
| 엉뚱한 게임이 나옴 | 3 | 10% | Planet of Lana → 에이지 오브 원더, Mega Man 11 → 다크소울 3, World of Horror → 월드 스토커 2 |

- 상품명이 전부 한글 표기라 "영문 이름이 제목에 들어 있는가"로는 맞고 틀림을 셀 수 없다. 위 분류는 상품명을 눈으로 본 것이다.
- 엉뚱한 게임이 나오는 것은 수집기가 걸러 내지 않는다. 정제기의 별칭 매칭이 거부해야 한다.

### 0건의 원인 확인 (같은 날, 한국어 표기 8건 + 0건 페이지 점검)
0건이었던 게임 8건을 한국어 표기로 다시 검색했다 (한국어 표기는 직접 정한 것이라 틀렸을 수 있다).

| 결과 | 게임 |
|---|---|
| 한국어로도 카탈로그 0건 | 브로타토, 벅샷 룰렛, 하이퍼 라이트 드리프터, 로그 레거시, 위저드 오브 레전드, 리스크 오브 레인 리턴즈, 피코파크 (7건) |
| 다른 게임이 나옴 | 전장의 발큐리아 리마스터 → 전장의 발큐리아 4 (1건) |

- **0건 페이지가 빈 페이지는 아니었다.** `브로타토` 페이지는 `count.total=4`였다. 그 4건은 카탈로그가 아니라 **개별 판매처 상품**(`TH201_…` 같은 번호)이라 수집기가 읽지 않은 것이다.
- 개별 상품을 열어 보면 `[해외] 브로타토 플레이스테이션 5`(G마켓, 115,620원), `[해외] 브로타토 닌텐도 스위치`, `[해외] 피코 파크 1+2 다국어`처럼 **해외 직구·수입 상품뿐**이다. 벅샷 룰렛과 로그 레거시는 게임 상품이 아예 없었다(낚시용품·의류가 나옴).
- 이런 `[해외]` 상품은 정제기(`console.py`의 `OVERSEAS`)가 어차피 거른다.
- **결론: 한글 이름이 없는 게임의 0건은 대부분 "다나와에 국내 판매 카탈로그 상품이 없다"는 뜻이다.** 검색어(IGDB 별칭·한국어 표기)를 늘려도 얻을 것이 거의 없다. 이 게임들은 eShop·PSN 다운로드로 파는 인디 게임이 많다.
- 한계: 영문 30건·한국어 8건 표본이다. 한국어 표기 4건(0건)은 개별 상품까지는 열어 보지 않았다.
- **서비스에 미치는 영향:** 한글 이름이 없는 게임 339건 중 상당수(표본 기준 약 70~80%)는 콘솔 가격이 비어 있을 것이다. 화면은 "콘솔 가격 정보 없음"을 보여 줘야 한다 (frontend·backend 확인 필요).
- 지금 방식(한글 이름 → 영문 이름)은 그대로 둔다. 0건 검색도 요청 10초를 쓰므로(339건 중 약 200건 ≈ 35분) 줄이고 싶으면 게임 선정 단계에서 콘솔 상품이 있을지를 반영하는 것이 맞다.

## 아직 안 한 것 · 알아둘 점
- **콘솔 본체 번들·액세서리·DLC·에디션이 섞여 온다.** 샘플에 `Microsoft XBOX ONE X 1TB … 사이버펑크 2077 번들`(898,000원)처럼 게임 카테고리에 있는 본체 번들이 있었다. 이런 거르기와 상품명 → 게임 매칭은 **정제기(`pipeline/refiner/rules/danawa_match.py`, PR #50으로 `main`에 합쳐짐)**에 구현되어 있다. 이 수집기의 실제 샘플 20개를 그 코드에 넣어 보니(별칭은 사이버펑크·유로 트럭 2개만 줌) 5개만 매칭되고 15개가 이유와 함께 걸러졌다: DLC·확장팩 7, 에디션 5, 비게임 2, 본체 번들 1. 수집기를 바꿀 필요는 없다(정제기는 `payload.product_name`만 읽는다).
- **빈 플랫폼 보강 검색**(`<이름> <플랫폼>`, 15개 후보에서 47건 추가)은 요청이 약 3배가 되어 6시간 주기를 넘길 수 있어 뺐다. 필요하면 별도 옵션으로 추가한다.
- 개별 판매처 상품(중고 최저가가 여기에 많다), 2페이지 이후, 상세 페이지 가격표는 이번에 뺐다 (danawa-notes 10·11절).
- 다나와 리뷰·가격 이력은 robots.txt 금지라 수집하지 않는다.
- Kafka 실제 전송 시험, 전송 실패 감지, 스케줄은 `igdb.md`와 같다. **스케줄이 2.3시간짜리라서, 6시간 주기에 겹치지 않게 실행 중복을 막아야 한다.**
