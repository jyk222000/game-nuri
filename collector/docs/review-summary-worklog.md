# 리뷰 요약 배치(⑤) 작업 기록 (11/24~11/25)

운영 방법과 앞으로 할 일은 `review-summary.md`에 있다. 이 문서는 **그동안 무엇을 어떻게 했고, 왜 그렇게 정했는지**를 남긴다.
숫자는 로그와 DB 조회에서 확인한 값이고, 확인하지 못한 것은 "미확인"으로 적었다.

## 1. 목표
- 게임마다 리뷰 장점·단점 키워드와 긍정률, 한두 문장 AI 요약을 만들어 `review_summaries`에 넣는다.
- 데이터 흐름: ES `reviews` → 수집 서버 배치 → Kafka `refined.review_summary` → Kafka Connect → MariaDB.
- 규칙: 리뷰 원문은 AI에 보내지 않는다(키워드만). AI가 실패해도 키워드는 보여 준다(`generated_by=fallback`).

## 3. 키워드를 뽑는 방식과 그렇게 정한 이유
- ES `reviews`의 한국어(`koreana`) 리뷰에서 `review.nouns`에 `significant_terms`를 쓴다. 긍정 쪽은 부정 리뷰를, 부정 쪽은 긍정 리뷰를 비교 대상으로 둔다.
- **점수는 `chi_square`(`background_is_superset: false`, `include_negatives: false`)로 한다.** 기본 점수(JLH)는 긍정 비율이 높은 게임에서 실패했다. 긍정 리뷰 집합과 부정 리뷰 집합이 서로 겹치지 않기 때문이다.
- 장점 키워드는 5개 이상의 리뷰에, 단점은 3개 이상의 리뷰에 나와야 한다(부정 리뷰가 적어서). 한쪽 최대 8개, 리뷰 30건 미만 게임은 건너뛴다.
- 한 가지 변경 사유: 한 게임에 부정 리뷰가 거의 없어도 장점만으로 요약한다.

## 4. 키워드 필터 이력
키워드는 리뷰 작성자가 쓴 글에서 나오므로 어느 게임에나 나오는 말, 평가만 담은 말, 욕설이 섞인다. 필터를 여러 차례 보강했다.

| 종류 | 방식 | 예 |
|---|---|---|
| 일반어·평가·감정어 | `STOPWORDS` (정확히 같을 때만) | 재미, 최고, 추천, 불쾌, 기분 |
| 가격 이야기 | `STOPWORDS` | 할인, 세일, 정가 (`가격`은 "가격 대비" 같은 장단점이 되어 남김) |
| 거친 말·민감한 말 | `SENSITIVE_WORDS` (정확히 같을 때만) | 부분 일치로 막으면 "게이머"까지 막혀서 정확히 같은 말만 거른다 |
| 욕설 | `PROFANITY` (부분 일치) + `PROFANITY_EXCEPTIONS` | 시발점 같은 보통 말은 예외 |
| 게임 이름 조각 | 이름 제외 | CSV의 `name_ko`(없으면 `name`)에서 뽑은 단어 |
| 다른 글자 | 한글·영문·숫자가 아닌 글자, 자음·모음만 있는 말, 영어 속어 | 러시아어, ㅋㅋ (게임 약어 `dlc`, `fps` 등은 남김) |
| 변형 | 별도 추가 | "불쾌"를 막아도 "불쾌감"이 남아서 따로 추가 |

AI 요약 문장에 욕설이 섞이면 버리고 fallback으로 보낸다.

### 4차 정리 (#145, 11/25)
- 계기: 사용자가 보여 준 화면(에이펙스 배틀로얄)에 걸러지지 않은 말이 많았다.
- 방법: 1,000개 게임의 장점·단점 키워드를 DB에서 모아 빈도 상위 150개씩을 직접 훑었다.
- 제거한 말: 인생, 추가, 기분, 익숙, 현실, 사랑, 경험, 존재, 이만, 오랜만, 비슷, 실제, 시절, 순간, 구간, 긍정, 흥미, 애매, 합리, 개연, 유기, 할만, 타임, 과제, 아포, 립스, 임어, 전작, 후속작, 원작, 시리즈, 유저, 진행, 유튜브, 회사, 인물, 환불, 최적, 세상, 세계, 시대, 인간, 남자.
- 장점 쪽에서만 거르는 말(`PROS_ONLY_STOPWORDS`): 지루, 어려움. 장점 쪽의 "지루"는 "안 지루하다"라는 뜻이 거꾸로이고, "어려움"은 문맥이 없다. 단점 쪽에서는 문제를 알려 주므로 남긴다.
- 쪼개진 조각의 정체를 데이터로 확인한 것:
  - `발련` → "씨발련", 리뷰 543건. 욕설이라 `SENSITIVE_WORDS`에 넣었다.
  - `임어` → "에임어시스트"가 "에임어시"로 잘린 조각, 리뷰 12건. 욕설이 아니라서 `STOPWORDS`로 넣었다(처음에 확인 없이 욕설로 분류했다가 고쳤다).
  - `아포`·`립스` → "아포칼립스"가 쪼개진 조각으로 추정(미확인).
- 정확히 같은 말만 거르므로 세계관, 최적화, 아포칼립스, 시리즈물은 남는다.

## 5. AI 호출과 한도
- Gemini 무료 등급 `gemini-3.5-flash-lite`: 분당 15회, 분당 입력 토큰 250K, **하루 500회**. 한도는 모델마다 따로 있고, 사양 판정(⑥)과 같은 모델·프로젝트를 쓴다.
- 실패한 호출(503, 시간 초과)도 하루 한도에 들어간다. 503은 한도(429)가 아니라 Google 쪽 과부하다.
- 성공률: 밤 약 50~57%, 낮 60회 중 57회(95%). **낮에 잘 되는 것이 시간대 때문인지는 표본이 하나라 미확인.**
- 하루 한도(RPD)는 태평양 자정에 초기화되는 것이 아니라 최근 24시간 합계처럼 움직이는 것으로 보였다(차트 모양에서 추정, **미확인**).
- 제어 장치(`AiBudget`): 호출 상한(`--max-ai-calls`), 호출 간격 6초, 연속 3번 실패하면 60초 쉬고 계속 실패하면 두 배씩 늘려 최대 600초, 연속 12번 실패하면 멈춤. 멈추면 이어서 할 `--skip` 값을 로그에 남긴다.
- 2단계로 나눈 이유: 1,000개를 한 번에 AI로 돌릴 한도가 없다. 1단계(키워드만)로 전체를 먼저 채우고, 2단계(AI 요약)는 하루에 조금씩 채운다.

## 6. 정한 것과 이유
| 결정 | 이유 |
|---|---|
| 모델은 `gemini-3.5-flash-lite` 유지 | 이 팀의 키로 동작을 확인한 모델이다. 한도 화면에 `gemini-3.1-flash-lite`가 별도 하루 500회로 보이지만 확인한 적이 없어 쓰지 않기로 했다. 사양 판정(⑥)은 정확도가 중요해 이 모델 그대로 둔다 |
| 키·프로젝트·계정을 늘려 한도를 늘리지 않음 | 한도는 프로젝트 단위로 보이고, 우회로 읽힐 수 있다. 약관 문구는 확인하지 못했다. 사양 판정까지 같은 계정이다 |
| 타이머(systemd)로 자동화하지 않음 | 이어서 할 `--skip` 값을 사람이 정해야 하고, 한도를 사양 판정과 나눠 쓰기 때문 |
| 2단계 중 `--no-ai` 금지 | 같은 게임을 fallback으로 덮어써 AI 요약이 지워진다 |
| 필터를 바꿔도 앞쪽 293개만 AI로 다시 돌림 | 뒤쪽은 AI 요약이 없어 `--no-ai`로 키워드만 다시 만들어도 잃는 것이 없다 |
| 하루 호출은 약 400회 이내, 사양 판정용 100회 이상 남김 | 사양 판정 시연이 한도를 쓴다 |
| 11/29·11/30에는 돌리지 않음 | 발표 직전에 한도를 써서는 안 된다 |

## 7. 시행착오 (같은 실수를 피하려고)
- 성공률을 27%로 잘못 계산했다. 실제는 57%였다.
- "ES에 리뷰가 없다"고 의심했지만 ES에는 게임마다 약 500건씩 있었다.
- 사용자가 준 화면 두 장의 값(65와 0)을 같은 값으로 잘못 읽었다.
- 필터를 한 번에 완성하려 하지 않고, 실제 키워드를 보며 네 차례에 걸쳐 고쳤다. 1,000개 게임 전체를 한 번에 훑은 것이 가장 효과가 컸다.
- 서버 명령은 사용자가 실행하고, 파일을 고치기 전에 허락을 받는 방식으로 진행했다.

## 8. 아직 남은 것
- 게임 이름의 한글 표기(예: 에이펙스)가 키워드로 남는다. 게임별 별칭이 필요하며 방법은 정하지 않았다.
- 4차 정리는 빈도 상위 150개만 봤다. 그 아래에 비슷한 조각이 더 있을 수 있다.
- 앞쪽 293개는 옛 필터 기준이다. 11/26 낮에 `--ai-only --skip 0`으로 다시 돌린다.
- 3번 연속 실패한 게임(예: 111469, 25076, 7360)은 `--game-ids`로 다시 돌린다.
- 화면: 요약이 없는 게임은 키워드만 보여서 "요약 준비 중" 안내가 필요하다(프런트, 아직 PR 없음).
- 한도 초기화 시점, 낮 성공률이 높은 이유, 3.1 Flash Lite 품질은 미확인이다.
- 서버 설정 문서(infra PR #139)는 김준영 님 리뷰 대기 중이다.
- `docs/decisions.md`에 위 결정들을 한 줄씩 남기는 일이 남았다.
